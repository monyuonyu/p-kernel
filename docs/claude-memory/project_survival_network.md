Collective 層の宇宙生存版。逐語レポート＋実装マッピングは

**実装への合流点（重要）:** この構想の §7「分散ゲーティング」は、ちょうど
[[project_regions_architecture]] の **R3（未着手・本丸）そのもの**。現状の
`arch/common/moe.c` の `select_expert()` は per-source スコアを全員へ broadcast し
**グローバル最大値**を取る＝準・中央集権（regions.md §1.2 が自己診断）。§7 はこれを
**局所勾配を下る**形へ置換せよ、と要求する。gossip(swim.c)＋degrade.c の capacity(N) は
「局所状態を近傍に出す」配管として既にある。足りないのは意味づけ（流すのは余力/逼迫の
勾配信号、選ぶのは勾配の下流ノード）。

**ピア指摘と、その答え:** 素朴な勾配引き寄せは**発振**する（応援殺到→過剰→引き上げ→
再逼迫）。§8 の二層構造がそのまま安定化処方 = 生体の脊髄反射(速い時定数・局所閉ループ)／
大脳(遅い時定数・大域)。実装は勾配信号にヒステリシス/減衰の時定数を持たせ層ごとに分ける。

**次の一手（合意待ち・2026-06-06 時点）:** §10 ステップA を、カーネル本体に触る前に
**ホスト上の純シミュレーション**で。30〜100ノード・同時多発イベント・中央なし勾配
ルーティングを可視化付きで回す。検証3点: 同時多発で綺麗に分散(§5)／ノード破壊しても
機能維持(§3)／中央の不在を構造保証(§7)。expert選択は当初「距離＋負荷」の単純関数で良い。
置き場所候補: `samples/12_survival/` か `tools/sim/`（要相談）。branch は feat/regions-r0。

## 呼吸するパラメータ（R3b の設計方針）― 2026-06-06 mk_pino 提示
**「NN のパラメータ数・ニューロン数そのものが、網に参加するデバイス数の関数として
増減する。減るときはニューロン数自体が動的に縮退する」** — 固定パラメータ数は設計思想に
反する。実装方針は道B=**ニューロンはデバイスに宿る疎なエキスパートとして増える**:
新デバイス参加=新しい小FFNエキスパート群が現れ、§7ルーターが疎に発火させる(加算的=
既存関数を壊さない)。デバイス死=そのニューロン群消失をルーターが迂回=それ自体が縮退
(DKVAのKV喪失と同じ優雅さ)。道A(密なd_model動的伸縮)は関数破壊的なので採らない —
r3-model-widening.md の「widthは再プロビジョニング」前提をこの方針で上書きすること(doc更新TODO)。
部品は全部ある: 重み置き場=p-fs(F4の重みブロック)、シャード配置=HRW lookup、
発火=§7+§8、生存=world map。装甲板=細胞=ニューロンの文字通り化。
現状の呼吸: KV(DKVA)✅ エキスパート数(MoE=ノード数)✅ / モデル幅・ニューロン数=
コンパイル時定数❌(dtr.h)。R3b=「join で精度が上がり leave で優雅に下がる」を数値で示す。

## 全体状況マップ（分散・collective situational awareness）― 2026-06-06 追加

mk_pino が設計思想の一部として明示。§7 分散ゲーティングの**双子**。ゲーティングが
「局所信号で発火を決める」なら、これは「**宇宙全体に広がったネットワークの全体像**を
システム自身が知覚できるようにする」観測層。見たいのは:
**どこが発火していて/どこが暗いか**(活動マップ)、**どこに何のデバイスがいるか**
(実体マップ: 誰が・どの種類のデバイスで・どの位置/region に)。「人類全体の脳」を
文字どおりにする — 脳が自分のどの領域が光っているかを見られる。

**最重要の制約**: ゲーティングと同じ。**中央の集約サーバを置いたら §7 の禁則
(潰せる一点)に逆戻り**。だから可視化層も分散でなければならない — 各ノードが gossip
だけから自分のワールド像を組み立てる。一望図はあるが、それを保持する中央は無い
=可視化層も「一点突破で殺せない」。

設計の骨子(survival-network.md に書く予定):
1. **自己ビーコン**: 各ノードが軽量な自己状態を定期 gossip
   `{node_id, device_type(arch/role), region_id, pressure(load-cap), firing(どのclassで活性), age}`。
2. **ワールドテーブル**: 受信ビーコンから全ノード像を鮮度(age)付きで保持。古い/欠けは
   「不確実」として扱う(§10 の古さ・不完全さの明示)。
3. **状況ビュー**: `world`/`map` コマンドが**カーネル自身**で全体像を描く(最初はシェルの
   テキストマップ)。将来 UMP アプリが同じフィードを食って実地図を描く。

**SHIPPED 2026-06-06** (`95ac916`, feat/regions-r0): world map 第1版が着地。
`arch/common/world.c/.h`(自己ビーコン→per-source topic `world/beacon/<id>`→ローカル
ワールドテーブル(age付き)→`world`/`map` テキストビュー)。device_type/region/pressure/
firing/staleness を中央なしで表示。`kdds_open_poll()`(zero-sem handle)を新設。デバイス
種別の gossip 経路もここで実装済み。残: bare-metal シェルへの露出、UMP アプリ連携、
pressure/firing の精緻化。詳細は [[project_regions_architecture]] 第1波記録。

カーネル現状の材料: `dnode_table[]`{node_id,ip,state,missed} + `swim` per-node RTT
(=遅延=空間距離の代理) + `region.c` + `moe` の per-node score。**足りないもの**=
①デバイス種別が gossip されてない(DRPC_PKT/DNODE に arch/role 欄なし) ②「発火/load」を
状況信号として周知する経路がない。この2つが新規実装ポイント。**スコープ合意**:
カーネル内の可観測性機能として実装(2026-06-06, AskUserQuestion)。

## 俯瞰監査 第2版の核心結論 ― 2026-06-07（philosophy-gap-audit-2.md, master 448e294）
第10波で穴を多く塞いだ後、自前の批判器官に「ループは本当に閉じたか」を俯瞰させた。結論:
**「閉じた制御ループではなく、個別に緑の鎖」**。三つの切れ目: (a)行動が dtr 経路・手動取り込み
にしか配線されてない(G16/G17: moe_infer は reflex を叩かない、SHIELD は対話 shell の
selfc/genome のみで自動発芽経路を覆わない) (b)**網規模の熟慮=学習が空**(G18: fedlearn 分散は
E_NOSPT、§2「守る対象」の実体なし=第三レビューの「熟慮層が空」がまだ閉じてない) (c)一周を
連続実行・回帰防御する仕組みなし(G19)。加えて**行動が知覚を変えない→負帰還でなくフィード
フォワード**。最も効く第10波の副作用=**G12 🔴: degraded(k/n) の数字が world-gossip 鮮度依存で
嘘をつきうる**(G2 が「黙って成功にしない」ため期待集合を gossip 由来 region_id で組んだ結果、
coordinator ビーコン未着だと過大計上→誤った degraded。honesty 規約 I4 の核を過渡期に条件付き
裏切る)。他: G13(同時多発が multi-region で coordinator_aggregate 200ms 同期窓により再直列化、
「同時多発∧region横断」は未検証)、G15(認証が単一グローバル静的PSK+既定無認証=新たな中央的
トラストアンカー)、G14(同時性の帯域上限「数個」)。**→ 第12波標的候補: G12(gossip非依存の正直な
degraded)、ループを本当に閉じる(行動→知覚の負帰還、moe_infer に reflex 配線=G17、熟慮層に学習を
入れる=G18)、複合シナリオテスト(殺す∧同時多発∧記憶 を同時に=G19)。** 思想的に最重要なのは
「鎖を環にする」= survival-network.md の「考える器官」が反射だけでなく**経験から学んで自分を
書き換える環**になること。

## 俯瞰監査 第3版 ― 2026-06-07（philosophy-gap-audit-3.md, master 7141928）★最重要
第12波で「鎖を環にする」を試みた**最中に**、自前監査が**まだ統合してない味方A隊の成果を予防弾劾**。
- **G20 🔴 符号の倒錯（最重要）**: `pressure` が「混んでる(送るな)」と「危ない」の両方を単一スカラで
  表すのに `expert_utility` は一律ペナルティで引く(moe.c:159)。reflex CONSERVE が +40 し
  (reflex.h:67)、world_observe で自ノードも自分の pressure を載せる(world.c:294-307)。結果
  **脅威を観測したノードは自分の緊急推論を遠方へ送り出し、近傍も alarm 連鎖で避ける**=
  survival §2「全網の力を一点へ注ぎ込む」の**真逆の符号**。守るべき一点に集中するどころか
  仕事を逃がしている。
- **G21 🔴 自己申告の閉ループ**: reflex 解除は REFLEX_HOLD_MS=5000 固定タイマのみ
  (reflex.c:243-257)。脅威を縮める actuator が無い=「沈静化した」観測はタイマ満了であって
  環の収束でない。**外乱の自然減衰を収束に見せる偽の閉ループ**。→A隊の「負帰還」が本物か要厳格検証。
- **G24 🔴 最上位目的に三点欠落**: p-fs durable backend は TODO・P0 は in-memory
  (pfs_block.c:13-24)=**全ノード同時電源喪失で全損(まさに大災害シナリオ)**、配るペイロードは
  玩具ゲノム635param で人類知でない(genome.c:280-296)、再起動手順オブジェクトが不在(grep ゼロ)。
  「人類が滅んでも生き残り再起動する」に対し**図書館がまだ揮発メモリ**。
- **G23 🔴 論理層32頭打ち**: DNODE_MAX=32(drpc.h:35)が全配列幅、region は32を分割するだけ、
  上位フェデレーション無し=「数千ノード」への橋が無い。
- **G22 🟡 熟慮=学習でなく適応則実行**(fedlearn分散E_NOSPT、局所学習も b3 6個の有限差分のみ)。
- **G25 監査運用自体の死角(メタ)**: ①エネルギー/性能を一度も測らない(§4の存在理由が光速とエネルギー
  への答えなのに) ②全実証が Linux/qemu で実機 survival 走ゼロ ③ユーザの近接目的(UMP Android
  フリート)でなく宇宙スケール思想忠実度を毎波再確認し「玩具ハーネスの緑」を再生産。
- **新発振リスク**: 相関した脅威下で近傍が一斉CONSERVE→pressure勾配が平坦化→助けが最も要るとき
  流れない。moe-osc テストは相関入力を注入せず見逃す。
**結論「環は位相的には閉じる見込みだが自己申告の閉ループ」**。→ **第12波A隊の成果は G20(符号)
/G21(actuator無し)で厳格検証必須**。統合前に「本物の負帰還か/間違った符号で閉じたか/タイマ収束を
偽装したか」を見る。**第13波標的**: G20符号分離(pressure を負荷/脅威の2軸に)、G21 本物のactuator、
G24三点(durable p-fs/人類知ペイロード/再起動手順)=思想の最上位、G23 上位フェデレーション、
G25 死角(エネルギー計測・実機走)。
