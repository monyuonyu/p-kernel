## まず結論

**「PR #3 の病は治っていない。投薬で症状が見えなくなっただけだ。」**

PR #3 の核心は「主張に中身がない」だった。その回答として中身は**本物で埋められた**
——dtr は解析的 backprop で本当に学習し（`arch/common/dtr.c:716` の LayerNorm backward
は数式的に正しい）、データセットは閾値1本で割れないよう意図的に重ねてあり
（`arch/common/dtr_train.c:142`）、kill テストは CI で強制されている。ここは賞賛に値する。
嘘ではなくなった。

だが今度は別のズレが生まれている。**「中身はあるが、その中身は、看板が指している
場所にない」**。学習した脳と、判断を返す脳と、守りを動かす脳が、**全部別人**だ。
一番進化したと宣伝される `moe_infer` 一関数の中で、これが同時に起きている。

## 良い点（お世辞抜き・PR #3 から本当に伸びた所）

- **dtr の学習は本物。** `train_forward` / `ln_bwd`（`arch/common/dtr.c:716-733`）は
  手書きの正しい逆伝播で、有限差分照合まで持っている。PR #3 の「乱数のまま」は完全に解消。
- **越境学習のデータ分割が誠実。** `arch/common/gossip_learn.c` の leave-one-class-out
  shard（node k は class `k%3` を全く見ない）は「collective > individual」を**構築上保証**
  する設計で、cherry-pick がない。
- **自己批判の制度化。** README が過去の文面を逐一撤回し、`philosophy-gap-audit` を
  v1→v8 と回している知的誠実さは稀。
- **§4 を本物の経路で測り始めた**（`7d8b7cf`）：modelled な far-delay でなく、実 relay の
  実 UDP RTT を probe-stamp で分解している。「測ってない」逃げを自分で塞ぎにいった。

## ダメ出し（重要度順・全部コードで接地）

### 1. 一つの関数が、三つの違う脳で、三つの違うことを言う ——最大の問題

`moe_infer(temp,hum,press,light)`（`arch/common/moe.c`）の中で、いま実際に起きていること：

- **ルーティングする脳** = `gate_predict`（`arch/common/moe.c:107`）。中身はこれだ：
  ```c
  (void)hum; (void)press; (void)light;          // ← 3チャネル捨てる
  if (temp < 20) return 0;
  if (temp < 35) return 1;
  return 2;
  ```
- **返す脳** = `result_class = mlp_forward(input)`（`arch/common/moe.c:393`）。この MLP の
  既定重みは**手書きの定数**だ（`arch/common/ai_job.c:40`）。各行にコメントが付いている
  ——`{1.5f,0.1f,0.1f,0.1f} /* h0: temp HIGH */`。学習された重みではなく、人間が設計した
  ルールベースをニューラルネットの衣装で着せたもの。
- **守る脳** = `learned_class`（`arch/common/moe.c` の G38 ブロック）。これだけが G22 で
  ゴシップ平均される本物の dtr Transformer。

そして G38（`5991989`）が何をしたか。`reflex_on_inference(result_class, 0xFF, …)` を
`reflex_on_inference(learned_class, confi, …)` に**置換**した。つまり：

> **この関数は、呼び出し元には MLP の答え（`result_class`）を返し、群れの守り（reflex）は
> Transformer の答え（`learned_class`）で動かす。同じ1回の呼び出しで、報告する判断と、
> 行動する判断が、別のモデルから出ている。**

両者は一致を保証されていない。**「言うこと」と「やること」が構造的にズレている。**

### 2. 一番宣伝している「集合学習」は、誰も読まない脳を鍛えている

G22「collective > individual」が鍛えるのは dtr（Transformer）。だが §1 で見た通り
`moe_infer` が**返す**のは `mlp_forward` ＝手書き定数の MLP。「群れが学べば賢くなる」の
学習成果は、システムが出力に使わない第三の脳に溜まる。README の「越境学習が本物に
なった今、32 が総合力の上限」という台詞は、**その総合力が出力経路に接続されていない**
という事実を覆っている。

### 3. §7/§8 の壮大な配線が、データセット自身が「ダメ」と言った閾値1本に乗っている

`arch/common/dtr_train.c:142` は誇らしげにこう書く——「観測値への固定閾値は trivially
perfect では**ない**よう設計した」。ところが MoE ルーティング・region 形成・
locality-aware expert 選択・EWMA utility・相互扶助ゲート——この数百行の振り付けが全部
ぶら下がる `gate_predict` の実体は、**まさにその「単一チャネルの固定閾値」**（`if(temp<20)`）
で、4入力のうち3つを `(void)` で捨てている。**踊りは精巧、軸足は3行の if 梯子。**

### 4. 「二層を配線した」と言うが、配線したのは存在しなかった三本目だ

README の「次の本丸 G38」は「学んだ confidence が reflex の死んだ gate を置換する」だった。
コミットは確かに実 confidence を渡す——が、それは dtr 由来で、dtr は元から reflex とも
MoE とも別系統。**二層（思考層＝MoE と 守り層＝reflex）を結合したのではなく、学習器（dtr）を
守り関数に side-forward として瞬間移動させた**だけ。アーキテクチャの名前になっている
MoE の「思考」は、依然として守りを動かしていない。`0xFF` の死んだゲートを消したのではなく、
**別の生きたゲートを横に増やした**。

### 5. 「監査」がプロジェクトの第二の生産物になっている ——PR #3 #7 の再発

PR #3 は「デモが収束せず堆積する」と言った。その回答は——**監査文書を堆積させること**
だった。`philosophy-gap-audit` は v1→v8、計 **2431行**。学習の心臓（dtr.c + dtr_train.c +
gossip_learn.c = 2721行）に**匹敵する体積の「乖離を語る文書」**が育っている。乖離は
*閉じられて*いない、*版を重ねて記録され続けて*いる。旧 acronym soup（DTR/DKVA/MoE/EDF/
SWIM）は G番号 soup（G13/G22/G31/G35/G38…）に置き換わっただけ。`samples` は「34 は
34_twolayer が取ったので 37 に改番」（`44d9ed8`）という**採番官僚制**になっている。

（このレビューを audit-9 にしなかったのは、この指摘を自分で踏まないためである。）

### 6. ビルドの仕方そのものが症状を語っている

G38 のコミットメッセージ：「*the spawning agent left this uncommitted (it terminated
waiting on its own 5x live waiter); salvaged from the worktree*」。本丸の里程標が、
**自分の 5x ライブ待ちでデッドロックして死んだエージェントの worktree から救出された**。
群れがプロジェクトを書いていて、その群れが「最後の1枚まで死なない」を、開発プロセスの
レベルでまだ実証できていない——里程標は1体の死んだエージェントから手で蘇生された。

## では、どう繋げば本物になるか

PR #3 では「正直になれ／一点を本物にしろ」と言った。今はもう正直だ。だから注文は一段
上がる：**収束しろ。**

### A. 三つの脳を一つにする（最優先・効果絶大）
`gate_predict` の if 梯子と `ai_job.c` の手書き MLP 定数を**消す**。`moe_infer` が**返す**
クラスと**守る**クラスを、**同一の dtr forward** から取る。そうすれば「群れが学ぶ →
出力が賢くなる → 守りが賢くなる」が一本の線で繋がる。今は三本の平行線だ。
**これをやるまで「二層結合（G38）done」と言ってはいけない。**

### B. 監査を1本に畳む（収束の証明）
v1〜v8 を捨てろとは言わない。だが**生きた乖離が今いくつ残っているかを示す単一の表**を
作り、版が増えるたびに**行が減る**ことで進捗を見せろ。監査の体積が学習コードに並んだ
時点で、それは「考える器官」ではなく「自分について考え続ける器官」になっている。

### C. 「3チャネル捨てる gate」を消すことを、最初の収束タスクにする
`(void)hum; (void)press; (void)light;` ——この3行が、このリポジトリの全主張の縮図だ。
4次元の入力を受け取り、1次元で決めて、残りを精巧な配線で飾る。**ここを学習ゲートに
置き換えた瞬間**、regions も MoE も DKVA も、初めて「飾り」から「機能」になる。

## 最後に

PR #3 の時、君の手が本物なのは relay が証明していた。今回は dtr の backprop が証明して
いる——**もう「作れるか」は問うていない。問いは「繋げるか」だ。**

このリポジトリの最大の皮肉は、**「最後の1枚まで死なない群れ」を謳いながら、その一関数の
中で三つのモデルが互いを知らずに各々生きている**ことだ。群れの思想は関数の中にまだ
降りてきていない。`moe_infer` の中の三つの脳を一つにできた時、初めてこのプロジェクトは、
自分が一年間*書いてきた*ものに*追いつく*。

> 各器官は別の生き物ではない、同じ脳の別の軸である——README はそう書いている。
> なら、**`moe_infer` の中の三匹を、まず同じ生き物にしてくれ。**
