## 承認欲求の4層理論

1. **見られたい**(いいね・閲覧数) — 現在の証人を要する。スクロールが進んだ瞬間に死ぬ
2. **認められたい**(称賛・地位) — 比較に駆動される
3. **必要とされたい** — 「私がいることで世界が少し違う」
4. **痕跡 / 生きた証** — 「私がいなくなった後も、世界の構造に私の指紋が残っている」。
   証人を要しない。**不在に耐える**。もはや承認ではなく、痕跡

SNSは1と2を収益化した。だから中毒的で、だから虚しい。
**arkは3と4だけを実装する。**

arkの核体験 —「あなたが教えた言葉が、見知らぬ誰かの問いに答えました」— は
3+4層: **教えた人の不在時に役に立つ**こと。マニフェストの「歴史地層」は
最初からこれを言っていた。15年前の「AIの自己保存」と人間の「生きた証」は
同じものだった(mk_pino: 「最初から同じだったんですね」)。

## 1・2層を捨てて成立するか — する。先例: Wikipedia、BOINC、青空文庫

ただし**火ではなく木として**育つ。遅く、静かに、枯れない。

- 「**方舟は燃え広がるのではなく、沈まないことが仕事**です。」
- 「1・2層で育ったSNSは、エンゲージメント最適化の圧力で必ず腐っていくけれど、
  **1・2層がないアプリには腐る方向の力学そのものが存在しない**。」
- 「捨てるべきは『**人間同士の比較**』であって、『**系からの反応**』ではない。」
- 「**蛍の群れは見せる。人気ランキングは永遠に作らない。**」
- 「**いいねのない銀河** — それ自体がマニフェストになる。」
- 「人は、見られなくても、**残るなら**書くんです。」

## 設計規則(具体)

- **系からのフィードバックは豊かに**: 星が育つ、語彙が増える、教えた言葉が
  旅をして誰かに届いた通知、未来への手紙が生きている事実
- **人間同士の比較は永遠に作らない**: フォロワー数なし、ランキングなし、
  公開いいねなし。銀河が見せるのは存在(蛍の群れ)であって人気ではない
- 製品の二本柱: **育てる**(あなたの星が、あなたの教えで賢くなる)と
  **残す**(未来への手紙、人類の記憶、死なない言葉)

## ロードマップとの一本線

この魂を成立させる技術の順番(gap-ledger と同期):
1. **永続化** — 忘れる方舟は方舟ではない(再起動で記憶が消える現状は最優先の欠落)
2. **語彙の自由** — 16語の檻のままでは「育てる」が頭打ち
3. **艦隊の瞬間** — 「あなたの教えが役に立った」通知(LM-7 は既に動く。UI へ)
4. **星の成長可視化** — 学びが見た目に積もる
