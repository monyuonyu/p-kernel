## 0. このドキュメントの立ち位置

`regions.md` が **空間**の話（近いノードを束ねる）だとすれば、これは **時間**の話である。
region は「どこまでが近傍か」を定義する。本ドキュメントは「**近傍は速く、全体は遅く**」という
時定数の分離を定義する。両者は同じアーキテクチャの直交する2軸であり、

- region（空間）= 反射層が閉じる**範囲**
- 時定数（時間）= 反射層と熟慮層を分ける**速度**

として噛み合う。`survival-network.md §8` は思想の核（逐語保存）であり、ここはその「どこに刺さるか／
なぜそう作るか」を埋める実装マッピングである。**思想は変えない。**

## 1. なぜ二層か — 光速が単一ループを禁じる

`survival-network.md §8` の出発点をそのまま引く：

> 宇宙全体の総合力を一点に集めようとすると、遠いノードほど応答に時間がかかる
> （地球‐火星で片道数分、より遠ければ数時間）。**秒速十数kmで迫るデブリには、遠方の
> 英知は間に合わない。**

ここに「単一の全体最適ループ」が原理的に成立しない理由がある。判断の質は集めるノードが多いほど
上がる（§4 MoE、§2 守る力の総体）。だが集めるほど遅くなる（光速）。**質と速度が物理的に
トレードオフ**で、しかも片道遅延は設計でどうにもならない定数（c）に縛られている。

時間制約のあるイベント（km/s デブリ、急な過負荷スパイク、リンク断）は、**応答が間に合わないなら
質はゼロと等価**である。火星の英知が「正しい回避策」を返しても、デブリが当たった後では意味がない。
したがって：

| | 時間予算 | 集められる範囲 | 最適化対象 |
|---|---|---|---|
| **時間制約イベント** | RTT 1往復ぶん | 近傍のみ（光速で届く） | **間に合うこと** |
| **非時間制約イベント** | 秒〜分〜時間 | 宇宙全体 | **正しいこと** |

この2つを**1つのループで処理しようとすると、速い要求が遅いループに引きずられて間に合わなくなり、
遅い要求が速いループに無理やり乗せられて浅い判断になる**。両方が劣化する。

> **§8 の生体アナロジー（脊髄反射 vs 大脳）が、そのまま設計原理である。**
> 脊髄反射は近く（脊髄）で速く閉じ、大脳の関与を待たない。だから熱い鍋から手が引ける。
> 大脳は遅れて状況を理解し、「なぜ触ったか」「次はどう避けるか」を学習する。
> **近傍が今を守り、全体が未来を強くする**（§8 末尾）。

二層は機能分割ではなく、**物理（光速）が強制する構造**である。中央を置けない（§7）のと同じ理由で、
単一時定数も置けない。

## 2. 第1層 反射層 — local / fast time-constant

反射層は「**光速で間に合う範囲の近傍ノードの群れ**」（§8 第1層）が担う。決定的なのは、
**反射の判断が大域の遅延に一切乗らない**こと。反射層の閉ループは region 内で完結する。

### 2.1 空間の境界 = region（RTT ≤ τ）

反射層の「近傍」を物理ではなくネットワーク遅延で定義するのが `region.c` である。

- **Region = 相互 RTT が τ 以内のノード集合**（`region.h: REGION_TAU_MS=50`、[regions.md §3.1](regions.md)）。
- τ はそのまま**反射層の最大時間予算**を意味する。region 内のどのノードへ呼びかけても、
  応答は τ 以内に返る——これが「光速で間に合う範囲」の工学的定義。
- RTT は `swim.c` の ping/ack に相乗りした実測の EWMA（`swim_rtt_ms()`、alpha=1/4）。
  region は SWIM の ALIVE 集合を RTT で部分集合化したもので、**物理トポロジや relay の有無に
  依存しない論理層**。

> つまり τ を選ぶことは「**何ミリ秒までを反射と呼ぶか**」を選ぶこと。region 設計（空間）と
> 反射層設計（時間）が τ で1点に繋がる。Phase D の Android フリートが本物の τ を教える
> （[regions.md §3.1](regions.md)）。

### 2.2 反射層に閉じるトラフィック = KDDS_SCOPE_REGION

反射のための密な通信は **region 内に閉じる**。`kdds` の `KDDS_SCOPE_REGION`
（`kdds.h:57`）がこれを担う：

> REGION: 自 region のメンバ (RTT≤τ) にだけ送る — region 内に閉じた密通信。（`kdds.h` 逐語）

- DKVA の Q/resp、MoE スコア、replica といった**チャター（高頻度・短寿命）**は REGION スコープに
  置き、配信ループはメンバ部分集合だけを舐める（[regions.md §3.4](regions.md)）。
- これにより各ノードが見るトラフィックは region サイズに比例し続け、全体 N には比例しない
  （O(region_size²) であって O(N²) でない）。**反射層は構造的に速い**。

### 2.3 反射層の自律調整 = 局所ゲーティング + 局所 autoregulation

反射層は「全体最大の専門家」を待たない。`moe.c` の locality-aware ゲーティングが既に
その芽を持つ（R1 部分実装）：

```c
/* arch/common/moe.c — expert_utility(): 賢さ(accuracy) から近さ(RTT) を引く */
W expert_utility(UB accuracy, UW rtt_ms)
{
    return (W)accuracy - (W)(rtt_ms / MOE_RTT_MS_PER_POINT);
}
```

- 反射層では **utility に region 内優先を効かせ、近いノードを選ぶ**（[regions.md §3.3](regions.md)）。
  「賢いが遠い」より「そこそこ賢く近い」を選ぶ——尾の重い応答時間を切るのは反射層の責務。
- 局所 autoregulation = §6 応援・受援の**速い側**。逼迫した場所の周囲に勾配ができ、region 内の
  余力ノードがそれを下って流れ込む（§7 設計指針）。中央の指揮者なしに、局所シグナルだけで
  即時に再配分する。

### 2.4 反射層に属する決定（What belongs here）

- 即時の収縮・遮蔽・回避（§8 第1層「危険を感じたら即収縮・遮蔽・回避。今を守る」）。
- 過負荷の即時オフロード（region 内の余力ノードへの応援要請）。
- リンク断・ノード故障への即時切り離しと役割引き継ぎ（§3 一点突破で殺せない構造）。
- SOLO 縮退の即時発動（`degrade.c`: SOLO 遷移時に `replica_scatter_all()` を即時呼び出し、
  孤立に備える）。**孤立してもなお脳である**（[regions.md §4 不変条件](regions.md)）。

**反射層の判断は「正しい」を保証しない。「間に合う」を保証する。** 正しさの補正は熟慮層が後から行う（§7）。

## 3. 第2層 熟慮層 — global / slow time-constant

熟慮層は「**時間をかけてよい深い判断・学習・設計更新**」（§8 第2層）を、宇宙全体の総合力で担う。
ここでは光速の遅延は許容される——というより、**遅延を払ってでも範囲を広げる方が得**な判断だけが
ここに来る。

### 3.1 大域の疎な交換 = GLOBAL gossip + cross-region 集約

- `KDDS_SCOPE_GLOBAL`（`kdds.h:57`）は coordinator 間の疎な交換に使う。region 間は coordinator が
  ゲートウェイとなり、**要約だけ**を流す（[regions.md §3.4](regions.md)）。
- DKVA の **rsum**（region summary）がその実体：各 region の coordinator が自 region の集約結果を
  `rsum/<rid>` (GLOBAL) に出し、requester が region 間でそれを畳む
  （`dkva.c:111,210,252-265` / R2 の2段集約。`dkva.c:330` `rsum_cnt`）。
  これは「region 内で部分集約 → coordinator が region 間で再集約」という階層集約そのもの。
- `world.c` の状況図（decentralized whole-network situational-awareness map）は、熟慮層が
  **全体像を遅れて獲得する**ための器官。`world_note_firing()`（`moe.c:177`）が発火を記録し、
  全体の状況がゆっくり形になる。

### 3.2 熟慮層に属する決定（What belongs here）

- 全体最適なリソース配分の見直し（応援・受援の**遅い側**——速い振動に乗らない裁定）。
- 学習・重み更新・設計更新（§8 第2層「未来を強くする」）= **regions R3 の本丸**：
  `fedlearn.c`（連合学習）／`ga.c`（進化）／重みの provisioning（[regions.md §6](regions.md)）。
- capacity(N) のバンド判定の安定側。`degrade.c` の SOLO/REDUCED/FULL や `capacity_score()` は、
  瞬間値ではなく**均された傾向**で動かす（[regions.md §3.2](regions.md)）。
- region の再編成・τ の調整・ルーティング表の一貫性（eventual で良いか、raft で合意か）
  （[regions.md §6](regions.md)）。

**熟慮層の判断は「間に合う」を保証しない。「正しい」と「学習」を担う。**

## 4. 時定数とゲーティングの安定性 — このドキュメントの核

ここが §8 が存在する**本当の理由**である。`survival-network.md §II-3`（発振への処方）が予言した
問題を、設計として詰める。

### 4.1 単一時定数だと発振する（なぜ §7 の素朴実装は壊れるか）

§7 の分散ゲーティング（局所勾配で応援が流れ込む）を、**1つの時定数**で素朴に実装すると、
古典的な制御不安定——**リンギング**——を起こす：

1. ノード A が逼迫し、余力勾配を近傍に発信する。
2. 周囲の余力ノードが**全員同時に**勾配を下り、A（または同じ「空席」スペアノード）へ殺到する。
3. 殺到先が今度はスパイクして逼迫信号を出す（過剰補正）。
4. 全員が一斉に引き上げる → 再び空く → 再び殺到。

これは「センサ（逼迫信号）→アクチュエータ（応援移動）」のフィードバックループに、
**観測遅延（gossip 伝播）より速いゲインを与えた**ときに必ず起きる**位相遅れ発振**である。
スペアノードが踏み潰され（stampede）、スパイクし、全員が逃げ、また戻る——**ringing**。
負荷分散の話に見えて、実は制御理論の話だ。

### 4.2 構造的な解 = 2つの分離した時定数

§8 の二層構造が、そのまま安定化処方になる（`survival-network.md §II-3` 逐語）：

> - **反射層**: 近傍のみ・速い時定数・局所閉ループ。即応はここで閉じる（大域の遅延に乗せない）。
> - **熟慮層**: 大域・遅い時定数。奪い合いの速い振動に乗らない。
> - 実装上は **勾配信号にヒステリシス／減衰の時定数**を持たせ、層ごとに別の時定数を与える。

なぜ2つに「分ける」ことが解になるのか：

- **反射層（速い）にはヒステリシスを入れて発振を殺す。** 応援に行く閾値と引き上げる閾値を
  ずらす（デッドバンド）。一度応援に入ったら、逼迫が**十分**収まるまで引き上げない。これで
  「殺到→即引き上げ→再殺到」の高周波振動が消える。`region.c` の再編成が既に同じ思想を採る——

  > 再編成: RTT が τ を跨いで悪化／改善したら region を移動。…**（ヒステリシスで振動を防ぐ）**
  > （[regions.md §3.1](regions.md)）

  反射層のゲーティングにも同じヒステリシスを与える。

- **熟慮層（遅い）はそもそも速い振動の帯域を持たない。** 大域の裁定は gossip 伝播より遅い時定数で
  動くので、反射層の高周波振動を**観測しない**（ローパスフィルタとして機能する）。熟慮層が
  反射層の瞬間スパイクに反応しないことが、層分離の安定性の本質。

> **核心（3-4文要約）**: §7 の分散ゲーティングを単一時定数で実装すると、観測遅延より速いゲインの
> フィードバックループになり、スペアノードへの殺到→スパイク→一斉退避→再殺到という位相遅れ発振
> （ringing）を起こす。構造的な修正は、ループを**2つの分離した時定数**に割ること——速い反射層には
> ヒステリシス／デッドバンドを与えて高周波振動を殺し、遅い熟慮層はそれより低い帯域で動くことで
> 反射層のスパイクを観測しない（ローパス）。これは負荷分散の最適化ではなく**制御安定性の問題**であり、
> 2つの時定数を物理的に分けること自体が減衰（damping）になる——だから §8 の二層構造が存在する。

### 4.3 ゲーティング作業に必要な damping への接続

`moe.c` の `select_expert()` は現状ヒステリシスを持たない（瞬間 utility の最大を取るだけ）。
ゲーティングを §7（局所勾配）へ転換する作業（[regions.md §3.3 / R1–R3](regions.md)）には、
**utility に時定数を与える damping** が必須になる：

- 切替閾値のデッドバンド（今のエキスパートから乗り換えるには、新候補が現行を**マージン分**上回る必要）。
- utility の EWMA 平滑化（RTT EWMA と同じ思想を accuracy/負荷信号にも適用）。
- 「region 内に閉じる」こと自体が damping——大域の遅い信号を反射ループから締め出す。

これは最適化（より賢い選択）ではなく**安定化（振動しない選択）**であり、ゲーティング作業の
正しさの前提条件である。

（モデル）」の順。各段は単体で観測可能な価値を出す。

| 段階 | 内容 | 依存 | 整合 |
|---|---|---|---|

## 7. 正直な論点 / 未解決

1. **反射と熟慮の和解（最難関）**: 反射層が「今すぐ回避」を決めた後、熟慮層が「その回避は最適でなかった」
   と遅れて結論したとき、どう折り合うか。反射の決定はもう実行済み（手は引っ込めた後）。熟慮は
   **過去を覆せない**——できるのは**次回のゲイン/重みを更新する**ことだけ、と割り切るのが筋に見えるが、
   実行中の長い動作（継続的なオフロード等）を熟慮が**途中で上書き**してよいかは未定。上書きを許すと、
   §4 の発振が層をまたいで再発する恐れがある。

2. **二層が真っ向から矛盾したとき**: 反射層が「region 内で対処可能」と判断し、熟慮層が「これは全体危機、
   大規模動員が必要」と判断したら、どちらが勝つか。生体では大脳が脊髄反射を**抑制**できる
   （随意で熱いものを掴み続けられる）。p-kernel でも熟慮が反射を抑制する経路を持つべきか、
   持つならその経路自体が中央化（§7 が禁じるもの）にならないか。**抑制の権限を分散したまま持たせる**のは
   未解決。

3. **region 境界での反射**: 反射層は region に閉じる前提だが、デブリのような物理イベントは region 境界を
   またぐ。境界ノード（複数 region に RTT≤τ で属しうる、`region.h` の egocentric ビューは
   ノード間で完全一致しない）は、どちらの反射ループに属するのか。両方に属すると二重応答／二重発火の
   恐れ。`region.c` の決定的 coordinator 選出だけでは境界の反射責務までは決まらない。

4. **τ が反射層の時間予算を決めてしまう**: τ を大きく取ると region が広がり反射の質は上がるが、
   反射の最大遅延（= 時間予算）も伸び、デブリに間に合わなくなる。**τ を下げる圧力（速さ）と
   上げる圧力（賢さ）が拮抗**し、§1 の質 vs 速度トレードオフが τ という1パラメータに凝縮される。
   静的閾値か動的クラスタか（[regions.md §6-5](regions.md)）に加え、**反射の時間予算からの逆算**で
   τ を縛るべきかは未解決。

5. **2つの時定数の比をどう決めるか**: 反射 tick と熟慮 tick の比が小さすぎると熟慮が反射のスパイクを
   観測して発振が層をまたぐ。大きすぎると熟慮の反応が鈍りすぎて「未来を強くする」が遅れる。安定限界
   （古典制御なら位相余裕）を**分散・非同期・eventual consistency の下でどう見積もるか**は、
   解析的な裏付けがまだ無い。当面は D0 シミュレーションの経験則に頼ることになる。

---

> 反射と熟慮は別の生き物ではない。**同じ脳の、別の時定数**である（[regions.md §7](regions.md):
> 「region は半球であり、別の生き物ではない」と同型）。近傍が今を守り、全体が未来を強くする——
> その2つを混ぜないことだけが、光速の壁の下で脳が発振せずに生き延びる道である。
