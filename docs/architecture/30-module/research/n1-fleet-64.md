# N1: 64 台を実際に走らせる（設計）

2026-10-26。ROADMAP の N1。探りは容器で 1 回（`pk-scratch/n1/`）。

## 1. いまの 32 台の試験

- 「実走 N=32 で 6/6」は `samples/11_distributed/run_Nnode_scale.sh`。aarch64 の `so_node` 用で、x86 の容器でも CI でも走らない（D5-e）。上限も `N≤32`
- 合格の 6 つ: ①中継に N 台が登録 ②node1 の `world` の known が N の 3/4 以上 ③領域ができる ④`infer` が結果を返す ⑤表の枯渇が 0 ⑥落ちたノードが 0
- 番号: 外の 1..64 は中で 0..63（usermain.c の `mac[5]-1`）＝既定の DNODE_MAX=64 のまま 64 台が入る

## 2. 探り（容器 4 コア、master 1f8f634d、x86_64 hosted、中継 1 台、0.15 秒おきに起動）

| N | 収束（known が全部） | node1 の領域・dkva の仲間 | 中継の受信 | RSS/台 | 6 項目の読み |
|---|---|---|---|---|---|
| 16 | 25 秒で 15/16 | 15 台・10 | 103 KiB/s | 84 MB | 全部緑 |
| 32 | 58 秒で 32/32 | 6 台・**0** | 120 KiB/s | 84 MB | 全部緑（④ は手元の 3 件だけ） |
| 64 | 210 秒で 25/64 止まり | 1 台・infer 返らず | **26 KiB/s** | 84 MB | ①59/64・② 赤・④ 赤、③⑤⑥ 緑 |

- 原因は **CPU**: 64 台で負荷 56・計 290%（4 コアを使い切り）。RTT が 40〜260 ms に伸び τ=50 ms の領域が 25 に割れた。中継への接触が時間切れの 5 台は「仮の relay・群れなし」（D5-i）に落ち、SWIM の自己疑い 13 回（16・32 台は 0）
- メモリは 84 MB/台で一定＝64 台で 5.4 G。中継の流量は CPU で決まっていた
- 待機の CPU（`idle1.sh`、40 秒）: 1 台 12.5%、4 台で各 13%、起動の 30 秒に各 6〜8 CPU 秒。**64 台の待機だけで約 8.3 コア**＝4 コアに入るのは 30 台ほど。何が食うかは未調査
- 交絡: idle の測定中に別の作業が 1 コア

## 3. 決めたこと（実装の回はこれに従う）

- 試験 `tests/host/run_fleet_live.sh`（x86_64 hosted、run_knowledge_survival.sh と同じ起こし方）、`FLEET_N` 2..64。32 台で緑を確かめてから同じ版で 64 台
- 合否: 6 つ＋**④′ dkva が領域の仲間を 1 台以上集めた**（④ の空振りの緑を塞ぐ）。⑥ に「最後に N 台とも生きている」を足す（元は起動後の死を見ない）。強くする向きだけ。③ の size≥1 は自分だけでも通る＝中身は ④′
- 記録 1 回 1 行: N・収束秒・known・領域の大きさ・dkva の仲間・中継 B/s/台・RSS・負荷・自己疑い
- 3 回ずつ、32 と 64 を交互に
- 陰性コントロール: ① `-DDNODE_MAX=32` の版を N=48 → ② 赤 ② 落ち着いた後に 2 台 kill -9 → ⑥ 赤 ③ `PKERNEL_RTT_ZONE_SIZE=1`（1 台ずつ）→ ④′ 赤
- CI には入れない（1 回 5 分・5.4 G）。容器で夜に
- **CPU の扱い（この順）**: (a) 起動は 8 台ずつ、前の組の `mind_net_task up` を待つ（試験の側だけ）(b) 全ノードに `stop now`（眠りの仕事を止める。このシナリオは学びを使わない）で待機の CPU を測り直す (c) それでも 64 台が 3 コアに入らなければ、**待機の費用を次の項目にする**。SWIM や接触の時間切れを試験だけ延ばして緑にはしない。τ は (a)(b) の後も割れるときだけ `PKERNEL_REGION_TAU_MS` で広げ、記録に書く

## 4. まだ言わないこと

1 台の機械の 64 プロセス＝ネットの遅れ・分断は無い。「64 台の実機」ではない。1 台あたりの帯域が N に依らないかは N3〜N4 の問い
