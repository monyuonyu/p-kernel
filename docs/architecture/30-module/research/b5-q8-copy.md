# B5: 周の写しを int8 で送る（設計メモ、実装 feat/b5-q8、監査-215 PASS）

2026-11-22 14:20 の回（研究）。b5-m-default.md §2 の G2（通信量）と G6（L は毎周断る）に効く 1 歩目。§4 の線は判定の種の前に 3efd5246 で固定。

## 1. 何が効くのか

- 周の写しは今 st_save の全部（w・mu・vu）。mu・vu は 0 だが塊に入る。数（容器、master 71d6b7b8、`sizes`）: M は rg_cap 22.8 MB・w 7.6 MB、**L は rg_cap 247 MB・w 82 MB＝上限 32 MB（8192 塊）を w だけでも超える**
- 行ごとの absmax int8（st_quant_fake の ST_QG_ROW と同じ格子、ノルムと router は fp32）なら M 1.96 MB（w の 0.258 倍）、**L 20.9 MB＝上限に入る**
- 原文（Konečný ほか arXiv:1610.05492 §3・§4）は「更新」を確率的に丸め、回転を掛け、2 bit でも損なしと報告。ここは重みそのもの・行ごとの尺度なので回転は不要、8 bit の偏りは単体で +0.0003（brain-quantization.md）。丸めは決定的に（全台で同じ塊＝試験が決まる）

## 2. 形

- magic を BRG2 に。中身は行ごとの int8 と fp32 の尺度、fp32 の残り（ノルム・router）。受け手は fp32 に戻して今の切り詰め平均と門へ。BRG1 も読む。古い受け手は BRG2 を数えない＝相手が減るだけ
- 送るのは周の写しだけ。Path W・保存・durable は変えない。hosted だけ＝crown は動かない（測った）

## 4. 合否（判定の種 261〜268、まだ誰も走らせていない、S）

- **Q0**（unit）: 戻した w は st_quant_fake(8, ROW) と全バイト同じ。BRG1 の写しも今どおり読める
