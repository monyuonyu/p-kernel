# B5 第 2 段: M の常駐の合体を既定に入れる条件（設計メモ、未実装）

2026-11-21 01:45 の回（研究、docs と測りだけ）。材料は master の D4b・D6b と b5-m-round.md。

## 1. いまの「既定」（コードの読み）

- `student_region_task` は `PKERNEL_B5_ROUND_S` が無ければ何もしない（r3_incontext.c `sr_period`）
- Android は JNI で tier M に固定（pkernel_jni.c 112）。PC は RAM と 4 コア以上で M
- L は publish が断る（塊 8192×4 KB＝32 MB まで、深さ 2 まで）。**6 コア以上で RAM が足りる PC は L**＝既定にしても毎周の断りだけ（G6）。既定は S・M だけにし、L は周のタスクを起こさない

## 2. 読みで見つけた、既定の前に要るもの（測る前）

- **G1 ごみ**: 生徒の塊は content-id で store に残り、消す道が無い（Path W には `mw_gc` がある）。周の間も DMN が学ぶ（d6m の held は周ごとに動く）ので毎周ほぼ全部が新しい塊＝1 台の store は 1 周で約 (1+仲間)×blob 増える見込み。M・1800 秒・仲間 4 なら 1 日 約 5.5 GB
- **G2 通信量**: 取り寄せは 1 周 4×22.8 MB＝91 MB、配りも同じほど。1800 秒なら 1 日 4.4 GB の受け。従量の回線と電池の Android には重い
- **G3 得**: d6m の n2 の 4 周で adopted は 1 回（ほかは門で断り）。合体の質は unit（W2b）だけで、live では測っていない
- **G4 CI**: 周は壁時計なので、コードの既定にすると多ノードの試験の最中に周が来る（🧭 11-18）
- **G5 無駄（測りの最中に読んで見つけた）**: 送る blob は st_save＝w・mu・vu（3 倍）。合体（既定の st_merge_trimmed も st_merge_cohort も）は仲間の w だけを読み、mu・vu は 0 に戻す＝運ぶ量の 2/3 は使われていない

## 3. 決めたこと（おすすめ）

1. コードの既定は 0 のまま。「既定」は製品の起動口が env を入れる（Android は JNI、PC は起動の台本）＝試験は今のまま
2. 入れる順: ⓪ G5: 送る写しの mu・vu を 0 に（電文の形は同じ。0 の塊は全台・全周で同じ id なので 1 度しか運ばれない）① G1 の片づけ: 消すのは「生徒の索引に載っていた id」だけ（方舟など他の塊を名指しでしか消さない）。仲間の塊は自分の合体が済んだら、自分の塊は 2 つ前の gen を publish の時に。いま publish している id は消さない。再起動で一覧が消えたら漏れる（消し過ぎない側）。ARK の店（`PKERNEL_PFS_BACKEND=ark`）では drop は表を空けるだけで記録は残る＝その店では既定にしない② PC を 1800 秒で既定に ③ Android は充電中かつ従量でない回線のときだけ（別項目）
3. Android の周は長く（例 21600 秒＝G2 が 1/12）。測ってから決める

## 4. 合否（測る前に固定）

- **X1（今の master を測る）**: S 5 台・120 秒・4 周。周の頭ごとに各台の store の大きさとファイルの数。予想: 周ごとに約 (1+4)×blob 増える。増え方が 2 周目以降も止まらなければ G1 は本物
- **X2**: 周ごとに増えたファイルの数＝取り寄せと publish の新しい塊。2 周目以降も 1 周目の半分以上なら「毎周ほぼ全部が新しい」は本物
- **X3（01:54 に足した、zmv の腕の結果を見る前）**: 送る写しの mu・vu を 0 にした写し（測りだけ、pk-scratch/b5md/zmv.py）を S・120 秒・4 周で。2 周目以降の 1 周の増えが X1 の 0.45 倍以下なら ⓪ は効く。合体の行（members 5 fetched 4）は X1 と同じ形のまま
- **D-G1（片づけを作ったら）**: 同じ測りで、4 周目の頭の store ≤ 2 周目の頭の 1.1 倍。陰性（片づけを外す）で赤。合体中・取り寄せ中の塊は落とさない（L1 が緑のまま）
- **D-1800**: run_b5_wire_live.sh を tier M・1800 秒で 1 回、master と同時（b5-m-round §5）
- **D-leave**: 周の途中で 1 台を kill → ほかの合体が 3P/4 の内に終わり、その台は gave up
