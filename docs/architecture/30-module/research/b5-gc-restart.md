# B5: 再起動をまたぐ片づけ（設計メモ）

2026-11-24 20:05 の回（研究、docs と試験だけ）。b5-m-default.md §6 の限界「再起動で gl_gc_ref が消える」を、M を既定に入れる前の次の 1 歩に選んだ。

## 1. 穴

- 片づけ（gossip_learn.c `gl_gc_note`）は `st/<node>` ごとの根（自分 2 世代・仲間 1 世代）を RAM の `gl_gc_ref` にだけ持つ。kill や電池の床での停止（Android の `stopSelf`）の後は空から始まる
- 店（PKERNEL_PFS_DIR）に残った前の世代の塊は、誰の根にも載らないので二度と消えない。生徒の塊を消す道は片づけしかない（b5-m-default.md G1）
- 見積もり: 1 回の再起動で残るのは自分の 2 世代と仲間ごとに 1 世代＝M の BRG2（約 2 MB）で仲間 4 なら約 12 MB。Android は止まって起きるのが常態なので、1 日 1 回なら 1 年で約 4 GB

## 2. 決めたこと（おすすめ、他の案）

- **根を店の横の小さなファイルに書き、起動後の最初の片づけの前に読む**。`gl_gc_ref` が変わるたびに `pfs_dur_write`（一時ファイル＋rename＋fsync）。中身は固定の大きさ（印・版・数・`GL_GC_REFS` 個の行、約 1.3 KB）。読めない・短い・印や版が違う → 読まない（今と同じ、何も消さない側）
- hosted だけ（片づけは `_TK_HOSTED_LIBC_` の中）。ベアの .text は変わらないはず＝実装の回が測る
- **作る回が確かめること**: 起動時の `pfs_dur_foreach` が店のファイルを全部読む＝このファイルを塊と取り違えない名前か（生徒の保存のファイルがどう避けているかを見る）
- 他の案: ① 起動時に店を掃く → 塊は内容アドレスで生徒の物と見分けられない ② 根を pfs の塊に → 決まった名前が要る＝ファイルと同じ ③ 塊に印 → 電文と店の形が変わる

## 3. 合否と陰性（実装の前に固定、2026-11-24）

試験: `tests/host/run_b5_gc.sh` に `B5GC_RESTART=1` の腕（relay＋5 台・S・120 秒・8 頭）。node 1 を 3 頭目の半周後（gen 3 を publish・合体した後）に kill -9、3 秒後に同じ店・同じ id で起こす。

- **R1**: 最後の頭で、node 1 の店 ≤ **1.03**（初めは 1.15）× node 2〜5 の店の最大
  - 監査-229（2026-11-24、実装の前）で締めた: 残る塊 1 個は約 173 KB＝店 3.02 MB の 1.057 倍。1.15 では「自分の 2 世代を戻し忘れる」半端な直し（1.11）が通る。各台は他が持たない自分の塊を 1 個ずつ持つ（node 1 だけが持つ 602 ファイル 1,209,614 B のうち 172,802 B は他の台にも同じ形で 1 個ずつある）＝直れば大きさは揃う（頭 1〜4 はバイトまで同じ）。位相を頭 4 の 1/4 周後にずらしても master は R1 赤 1.34（その位相では G1 は緑＝R1 だけが捕まえる）
- 同じ腕で G0〜G3（今の合否）も見る。素の腕（`B5GC_RESTART` なし）は ALL PASS のまま
- 陰性: 実装が足す `-DB5_NC_GC_NO_RESTORE`（ファイルを読まない）で R1 だけ赤。今の master も R1 赤（§4）
- 実装の回は crown（aarch64・x86 の .text）が master と全バイト同じこと、build_all を示す

- 素の腕: ALL PASS（K=3、8 頭とも 5 台同じ、頭ごとに +800 B）＝台本の書き換えで今の合否は変わらない

## 4b. 実装（2026-11-24 23:35 の回、feat/b5-gc-restart、監査待ち）

- gossip_learn.c の片づけの横に `gl_gc_load`・`gl_gc_store`。ファイル `gl.gcref` は 16＋16×sizeof(GL_GC_REF) バイトの固定（印 GCRF・版 1・枠の数・枠の大きさ）。読むのは最初の `gl_gc_note` の頭で 1 回、書くのは枠が変わるたび（同じ世代の繰り返しは書かない）で、**消す前に**書く。読めた枠が壊れている（used・own が 0/1 でない、n が keep を超える）なら全部使わない
- `pfs_dur_write`・`pfs_dur_read` は弱い参照（単体試験は pfs_durable.c なしで組む）
- 実装者の結果（容器 /build/gcr2、監査ではない、4 腕同時）: 再起動の腕 2 本とも ALL PASS・R1 1.000（5 台とも 3,021,202 B、node 1 は「restored 5 refs」）、陰性 R1 FAIL 1.343（G1 も node 1 だけ 1.34）、素の腕 ALL PASS。根のファイルで店は全台 +1,296 B
- **run_b5_d4.sh（CI の段）: ALL PASS（関門 W13c・W13d）。ただし報告だけの W13b は master の P=11 F=1（PASS）が P=13 F=3（FAIL）に**＝根のファイルの fsync 2 つ（ファイルと dir）が publish と merge で 1 回ずつ入る。根は停電を越えるべきなので fsync つきのまま（lazy の口に入れると関門 W13c が赤）。W13b は 11-19 から報告だけ（数えはプロセス全体で他の書き込みも入る、と台本の頭にある）
- 限界: 消している最中に kill されると、その世代の残りは根から外れたまま残る（窓は消す時間だけ）。根のファイルを手で消せば今の master と同じ（何も消さない側）

## 4c. 第 2 歩（2026-11-25 03:20 の回、監査-231 の 🔁GCR を受けて、監査待ち）

監査-231: 頭 4 の 1/4 周後の kill（仲間の gen を取り寄せている途中）で R1 赤 1.052・1.171＝途中まで来た塊は `gl_gc_note`（取り寄せが全部済んでから）を通らず、根に一度も載らない。読みで見つかった別の 2 つも一緒に直す。

- **取り寄せ中の欄**: `gl.gcref` を版 2 に（枠ごとに `pend`・`proot`・`pdepth`・`pnchunk`・`last`、頭に `tick`）。`gl_student_fetch_in` が記述子を確かめた直後・最初の want の前に `gl_gc_pend` で書き、`gl_gc_note` で消す。読み戻したときに残っていれば、先に欄を消して書き、守りの表（残す世代の全部と、索引が来ている範囲の取り寄せ中）を作ってから歩いて消す。同じ仲間の別の世代の取り寄せが始まったとき（前の取り寄せが gave up した）も、前のを同じく消す。陰性 `-DB5_NC_GC_NO_PEND`
- **枠の解放（①）**: 空きが無いとき、自分の枠以外で最後の変化が一番古い枠が `GL_GC_STALE`＝64 変化（全枠の note の数）以上前なら、新しい台に渡し、元の世代を消す（書いてから消す）。新しい枠は使用中の仲間から奪わない（64 変化は 16 台が 4 周ほど）。陰性 `-DB5_NC_GC_NO_EVICT`
- **読めない残す世代（②）**: 守りの表を作るときに索引が読めない世代は、その枠から外して書き、片づけは続ける（前は「cannot be read; nothing dropped」で以後ずっと止まった）。表が満杯（-2）は前と同じく何も消さない。陰性 `-DB5_NC_GC_KEEP_LOST`
- **2b（同じ回、上の 3 つでは h4q が赤のままだった）**: 直した枝で h4q の 2 腕は R1 1.114・1.143、「cut short」の行は 0＝kill は publish の後・合体の前で、取り寄せは走っていなかった（監査-231 の「取り寄せ途中」は外れ）。店の差と `.org`: 余分は再起動の 3〜5 秒後に仲間 3 台から来た gen 4 の一部（索引つき 26/43・37/43、索引の無い 21 塊）＝**boot SYNC**（`pfs_repl.c` `pfsr_sync_take` は RAM の表の塊を全部流す）。node 1 は次の周で gen 5 を取り、gen 4 は取らない＝根に載らない。直し: 応え手は自分が片づけの根に持つ世代（残す世代と取り寄せ中）の id を流さない（`gl_gc_holds`＝守りの表を引く、hosted だけ・弱い参照、陰性 `-DB5_NC_SYNC_STUDENT`）。生徒の塊は周の want でだけ動く（b5-wire2）。守りの表は note のたびに作り直す（消すものが無いときも）
- 根の書き込みは新しい世代の取り寄せごとに +1 回（fsync つき）＝報告だけの W13b はさらに増えうる
- 試験: `tests/host/run_b5_gc.sh` に `B5GC_PHASE=h4q`（直す前に足した）。単体 `tests/llm/run_b5_gc_slots.sh`（`-DGL_GC_TEST` のときだけの口で、仲間の役を試験がする。塊の id は試験が中身から計算＝索引を通さずに数える）: 17 台目・解放・取り寄せの中断・gave up・失った索引の 7 項目、陰性 3 つはそれぞれ自分の項目だけ赤。CI の llm の段（H36 の後、数秒）
- 限界: 自分の publish の途中の kill（塊を書いてから索引）は索引が無いので歩けない＝残る（窓は publish の時間）。索引を取り寄せている途中の kill（塊は索引が全部来てから取りに行く）は、深さ 2 なら根の索引 1 個（4 KB 以下）が残る

## 4d. 第 3 歩（2026-11-25 19:05 の回、監査-232 の 🔁GCR2 を受けて、監査待ち）

監査-232: h3q（頭 3 の 1/4 周後）の 1/4 腕で R1 1.057＝note が gl.gcref に新しい根を書いた後、犠牲（前の世代）を消す前に kill。犠牲はもう根でないので一生残る。試験先 `[gcs-vic]`（`gl_gc_test_cut_next`＝書いた直後で止める口、`GL_GC_TEST` だけ）。

- **犠牲を同じ書き込みに**: gl.gcref を版 3 に（枠ごとに `vpend`・`vroot`・`vdepth`・`vn`）。note は新しい根と犠牲を同じ 1 回の書き込みに入れ、消した後は RAM で消すだけ（次の書き込みが反映＝fsync は増えない）。読み戻したときに残っていれば、守りの表を作って歩いて消してから、欄を消して書く（消している途中の kill は次の起動でもう一度歩く。歩きは根の索引を最後に消す）。枠を解放するときも犠牲を消す。陰性 `-DB5_NC_GC_NO_VIC`
- 単体: `[gcs-vic]` は 75c87106 で 4/4/4 ids（赤）→ 直しで 4/0/0。陰性 NO_VIC は gcs-vic だけ、KEEP_LOST は gcs-holds・gcs-lost・gcs-vic（表が作れないので犠牲も消えない）
- `run_b5_gc.sh` に位相 `h4half`・`h3q` を正式に。窓に当たるのは偶然＝生きた腕は報告、決定的な合否は `[gcs-vic]`
- 限界: 深さ 2 の犠牲を消している途中で葉の索引が消えた後に kill すると、2 回目の歩きはその葉で止まる（後ろの葉が残る、測っていない。単体の世代は深さ 1）。表が満杯で消せなかった犠牲は、その枠の次の note で上書きされる（前と同じ）
