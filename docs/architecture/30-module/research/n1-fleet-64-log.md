## 64 台の C4P の赤（原因は未特定）

- node1 の Q に応答したノード: 2 回目 0 台・3 回目 48 台（1 回目は数えていない）。48 台が応答した回も node1 は 0 台を集めた
- 試したもの、どれも赤のまま（各 1 回）: 中継の -v を外す（落ち 11 万、応答 47 台）／2 台ずつ起動（tcp 16 台、落ち 9 万）／τ=250 ms（試験だけ、領域 33、応答 0）
- 候補（測っていない）: Q は 1 回きりの送信で窓は 600 ms、応答は領域の範囲だけに送る。UDP の落ちは 32 台でもあり（32 台は通る）、64 台で増える
- 次: Q と応答がどこで消えるかを数える探り（ノードごとの受信数）。直すなら Q の再送（応答側は req_id で重複を捨てる）が候補＝ベアの .text が動く
