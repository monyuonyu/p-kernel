# N2: 16 ビットのノード番号と版の交渉（設計）

2026-10-29。洗い出し `tools/n2scan/inventory.py`（正規表現、漏れあり）→ `n2-wire16-inventory.md`。

## 1. 8 ビットの前提（数は master e8b6c5f4）

- 電文・ディスクの形で 8 ビットの番号を持つもの **41 個・20 ファイル**（SWIM・K-DDS・dkva・pfs・mind ほか）。中継の頭は src・dst が各 1 バイト（8〜11 は予約で 0）
- **版が違えば黙って捨てる**（28 か所、ディスクを含む。網は drpc.c 404・swim.c 580・kdds.c 445 など）＝新しい版は旧版に届かない
- 0xFF＝「ノードでない」100 行、番号を添字にした表 377 行（DNODE_MAX＝64）、GOBJ は番号を 31..24 ビットに（使うのはベア x86）
- ベアは MAC の末尾から番号（1〜8）。hosted は種の hash を 1..63 に＝**8 台で 37% が衝突**（16 ビットでも 256 台で 39%）
- ノードの Ed25519 は**起動ごとに作り直し**（sign.c）。SWIM の incarnation は 1 バイト

## 2. 決めたこと

1. **幅で選ぶ（相手ごとの交渉はしない）**。0..254 の番号だけの電文は今の v1 のまま。255 以上の番号（「広い」）を 1 つでも含む電文だけ v2（番号 2 バイト）。一覧を運ぶ電文（SWIM のうわさ・pmesh の経路・mind/have）は狭い分だけの v1 と全部の v2 に分ける。新は両方を受ける。旧版は v2 を捨てる＝**広いノードは旧版から見えない**（＝「旧版が読める範囲」）
2. **v2 が読めることは SWIM の capability の bit 2 で言う**（今は予約）。1 台宛ての v2 はこの bit の立った相手にだけ。広い番号を v1 に切り詰めない（300 が 44 に化ける）
3. 中継は頭の予約 8・9 に番号の上位バイトを入れる v3（長さ 12 のまま、HMAC にも）。旧い中継は広いノードを拒む＝起動で 1 行言う。**本番の中継の入れ替えは人の仕事**。**v3 は「読める」と言ったノードにだけ配る**: 新のノードは v1/v2 の電文の頭の 10 バイト目に 3 を書く（旧版の MAC の外。偽っても配られるのは v3 の電文だけ）、v3 を送ったノードも読める扱い。旧版は v3 を鍵なしの v1 と読み（hdr が 12）、nonce と MAC を電文の頭として網の層へ渡してしまうので、中継が止める。広い番号は鍵が要る（v3 は v2 と同じ形）
4. 中の型は `pk_node_t`。ベアは UB のまま・v2 を作らない（ベアは 8 台まで）
5. **同一性**: hosted は Ed25519 の種を `node_seed` の横に残し、番号＝公開鍵の hash の 16 ビット。同じ番号で別の鍵なら大きい鍵の方が引き直す。v2 の incarnation は 2 バイト。許可の一覧は sign.c の allowlist（既定は空）。重みの署名は B5・0-9
6. drpc の GOBJ は狭い番号だけ（広いには E_NOSPT）

7. **引き直しの番号**: 番号＝`hash16(公開鍵 ‖ 引き直しの回数)`（0・0xFFFF と 1..254 を避ける形は N2c の実装で固定）。回数は `node_seed` の横のファイルに、引き直しを決めた時に fsync してから使う＝再起動しても同じ番号。ファイルが無ければ 0
8. **v2 の「ノードでない」は 0xFFFF**。0 も番号にしない。**中の「ノードでない」は 0xFF のまま**（1 バイトの欄・0xFF で埋めた表・比べが意味を変えない）＝255 は番号として出さない（PKERNEL_NODE_ID 256 は拒む、11-02 に決め直した）
9. **X5 の「同じ」**: 種を固定した 2 回の実行で、旧版が新の v1 の電文を 0 個落とし、capability の bit 2 を隠すと電文のバイトが一致すること（incarnation・時刻で揺れる欄は種で固定、固定できない欄は比べる前に名前を書いて隠す）

## 3. 段と crown

- **N2a** 型の名前だけ（電文は広がらない `pk_node8_t`、中は `pk_node_t`）。ベアの .text 不変が門
- **N2b** hosted で v2・bit 2・中継 v3、番号を添字にした表は nodemap.h（番号→枠）に。ベアは作らない＝crown 不変を測る
- **N2c** 鍵を残す・番号の引き直し・incarnation 2 バイト
- 255 台を**同時に**入れるのは N3（表の大きさ）。N2 は「広い番号が参加できる」まで

作ったもの（11-01〜02）: 中継 v3（広い番号は枠 256.. に一度取ったら持ち続ける、最大 768 個、貸し出しは v3 に無い）、hosted の net_relay.c の受けと送り（`heartbeat test` の 10 項目）。`pk_node_t` は hosted で 16 ビット、1 バイトの欄へは `pk_node_v1()`（広い番号は切らずに「ノードでない」に）＝`[n2-narrow]` で切り詰め 0。広いノードは MAC 52:54:00:00:hi:lo・10.1.hi.lo で起動し、v2 のビーコン（SWIM2_PKT、hosted だけ）で **SWIM の仲間の表にだけ**載る＝[n2-mix] X1・X2 緑。広い仲間は swim.c の nodemap（dnode_table の横）。

11-04（feat/n2b-self）: 番号→表の行は `pk_node_row.h`（行 0..63 は番号そのもの、ほかの番号は 32 の追加の行を最初に見た時に取って持ち続ける。表は drpc.c、hosted だけ）。**広いノードも drpc_my_node＝自分の番号で起動する**。自分を DNODE_MAX の表で引く所は、UBSan（-fsanitize=bounds、[n2-mix] の 7 台）が出した drpc.c・region.c・world.c と、読んで見つけた edf.c を直した（region は行で、ほかは `PK_NODE_IN_TABLE` で引かない）。ベアは元の式のまま。
監査-120 の FAIL の直し: 1 文字の名前の topic（`'0'+node` の world/beacon・reflex/alarm・moe/score・vital）は、広い番号を char に切ると狭いノードの名前になる（259→3 の、299→43 の）。広い自分はこれらを購読だけして出さない（`PK_NODE_OWN_TOPIC`）、`dtk_cre_sem` は -1。[n2-mix] の XT が見る。2 桁の名前（gossip_learn の `st/`・`dtr/model/`）も 263→「63」のように狭いとぶつかりうる＝K-DDS・PFS の名前の v2 の段で。

11-06（feat/n2b-region、段 (b)）: region_recompute は SWIM が ALIVE とする広い仲間のうち、v2 の往復が τ 以内のものを行でメンバにし、region_size に数える（[n2-mix] XG、陰性 `-DN2_NC_REGION_NARROW`）。限界: 狭い番号だけを回す呼び手（protect・dkva・lookup・kdds・moe・r3 の合体）は広いメンバを飛ばすのに、region_size は数える。

11-07（feat/n2-v2cap、1 台宛ての v2 の段 (a)）: hosted は SWIM の capability の bit 2＝「v2 が読める」を自分のうわさに立てる。狭い仲間の bit 2 は本人のうわさから bit 0・1 と同じ LWW の門で取り、cap_byte が中継でも運ぶ。`swim_peer_reads_v2(id)`＝狭い仲間はその表、広い仲間は SWIM が知っていて死んでいなければ真（v2 にしかいない）。旧版は bit 0・1 しか読まない＝bit 2 は旧版に何もしない（X5 の違いはこのバイトだけ）。試験 `nodes v2cap`、陰性 -DN2_NC_NOBIT2・V2IGNORE・V2WIDE_NO。旧版が中継したうわさは bit 2 を落とし、本人の同じ incarnation のうわさは LWW で負ける（incarnation は反論でしか上がらない）＝監査-147 で、bit 2 だけは本人（src＝その番号）の同じ incarnation の言葉から取る形に（毎周のビーコンで届く、陰性 V2DIRECT_NO）。次は段 (b): PMESH の DATA の v2（頭 14）を、src か dst が広いときだけ、読める相手へだけ送る。

11-07（feat/n2-pmesh-v2、段 (b)）: hosted の pmesh_send は宛先か自分が広いとき v2（頭 14、src/dst 2 バイト LE、中身 1378 まで）を、読める相手へ直にだけ送る（狭い相手は ALIVE も要る）。それ以外は -1 と v2_noread。受けは v2 の DATA を自分宛てだけ広い src のまま配り、他宛ては数えて捨てる（v2 の中継はまだ）。狭い同士は v1 のまま。受け手 5 つは src の引数で表を引かない。試験 `nodes pmv2`（送りの口に tap）、陰性 PMV2_NOCHECK・RXDROP。限界: 生きた群れで v2 を送る呼び手はまだ無い（kdds の中身の src も 1 バイト）＝X3 は赤のまま。自己試験の間は本物の送りも tap に吸われる。監査-148: 自分の番号が 0xFF（分散でない）なら v2 も送らない（v1 の門を v2 の道が素通りしていた、陰性 PMV2_NOIDOK）。監査-149: 受けも同じ＝自分の番号が 0xFF なら v2 を配らない（hosted は pmesh と kdds を起動時に結ぶので、偽の 255 宛てが届いていた。陰性 PMV2_RXNOIDOK）。
11-07（feat/n2-mind-wide-origin、段 (c)(3) の最初の一切れ、hosted だけ）: 広い先生の心の電文は 53 B の後ろに番号を 2 バイト LE で足し、origin_node は 0xFF のまま（旧版とベアは kdds_sub が受け手の 53 B で切る＝今までどおり 0xFF で捨てる）。受けは 55 B かつ 0xFF かつ尾が広い番号のときだけ尾を使い、origin ごとの seq は行（pk_node_row）で持つ＝300 は 44 の行を使わない。1 バイトの 64〜254 は今までどおり捨てる。試験 `nodes mtwide`、陰性 N2_NC_MT_SEQ_NARROW。限界: 尾を付けるのは自分の教え（発行と再送）だけ。pull の答えと押し返しは広い origin を運ばない。X3 には kdds の配り先（段 (c)(1)）も要る。
11-07（feat/n2-onlink16、hosted だけ）: netstack の next_hop は /24 で、広い番号の IP は 3 つ目のバイトを使う（300 は 10.1.1.44）＝広い⇔狭いの単一宛ては「別の網」として gateway へ回り、ARP が解けず黙って消えていた（広い同士は同じ /24 で通る）。[n2-mix] X3 の試しの合わせで、299 が 3・43 宛てに数百通送り、中継の送り口に 1 通も来ないのを探りで見つけた。自分も宛ても 10.1/16 なら直に、それ以外は /24 と gateway のまま。試験 `nodes onlink`、陰性 N2_NC_ONLINK24。

**まだ**: ほかの部品は広い番号を知らない（region のメンバにはなるが、呼び手は狭い番号だけを回す）。広いノードの v1 の欄は「ノードでない」＝[n2-mix] の X3（`N2_X3=1`、狭いノードと 260・300 の間の教え）は赤。広い仲間の生死は自分のビーコンだけ（PING なし）、広いノードは狭い仲間を死なせない。bit 2 は立てて読む（段 (a)）が、1 台宛ての v2 はまだ無い。snf・ss6 の宛先の IP は狭い番号の形のまま。net_relay_tcp.c は v3 を読まない＝広い番号は TCP で拒む。旧い中継の下で広いノードは入れず、ほかを乱さない（[n2-mix] N2_RELAY_OLD）。LAN は範囲外の番号を今も 1 にする＝広い番号はぶつかる

## 4. 混ぜる試験 [n2-mix]（合否は先に固定）

旧版＝N2 の前の master から作ったバイナリ（sha を記録）。容器で旧 3（1〜3）＋新の狭い 2（4・44）＋新の広い 2（260・300＝下位 8 ビットが 4・44）。

- X1 旧版の仲間は {1,2,3,4,44} だけ（幻なし）／X2 新は 7 台全部
- X3 旧 1 の教えは全員に、300 の教えは新の 3 台に届き、旧版は 44 の教えとして持たない
- X4 dkva は新の狭いで 7 台分、旧で 5 台分
- X5 全員が狭いとき、新の v1 の電文は旧版と同じ（違いは bit 2 だけ）
- 陰性: `-DN2_NC_TRUNC`（広い番号を v1 に切り詰める）で X1・X3 が赤、`-DN2_NC_V2ONLY`（狭い新も v2 だけ）で X1 が赤
- [n2-id]: 再起動で同じ鍵と番号。番号をわざとぶつけると 30 秒以内に分かれ、教えを取り違えない（引き直しを外すと赤）。64 台を全部広い番号で N1 の C の項目が緑
