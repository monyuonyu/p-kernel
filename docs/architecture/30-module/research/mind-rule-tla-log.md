## 2026-10-29 模型と最初の結果（実装の回。監査はまだ）

- 模型は C の今の形（master 3cd974e9 の r3_incontext.c）。設計に無かった細部を 1 つ入れた: **受け口は同じ値の教えを「重複」として捨て、自分のスタンプを変えない（5159）。そのときも送り元の seq の除け（5139）は使い切る**
- **今の C は S3 で P1・P2 が破れる（落ち 0）**。筋（10 状態）: n0 が v1（1,t0）、n2 が v1（1,t2）、n1 が v2（1,t1）を教える → n2 に n0 の v1 が「重複」で届き (1,t2) のまま → n1 の v2（1,t1）が (1,t2) に勝つ → n0 の v1 の再送は除けで全部捨てられる＝n0・n1 は v1、n2 は v2 のまま網が空。mind/have は持たない鍵しか欲しがらず（4464）、mind/hist は値を変えない＝治らない
- S4（教え 2）は今の C でも通る（同じ値の教えが 2 つ要る）
- **直しの候補 DupAdopt（同じ値でスタンプが勝つなら、値は変えずにスタンプと教え手を取る）で S3 は P1・P2・P3v・P4・P5 が通る（167 万状態、119 秒）**。ただし設計どおりの P3（教えのスタンプと教え手まで一致）は破れる: 同じ値の別の教えに吸い込まれた教えは、その (s,t) では履歴に残らない（値は残る）。P3v（値で見る）は結果を見てから足した＝線は P3 のまま
- 壊し方（直しの模型の上）: M1→P5（282 状態）、M2→P1（4,764）、M3→P1（3,903）。どれも狙いの性質で反例
