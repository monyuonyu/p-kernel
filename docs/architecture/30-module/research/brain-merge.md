# 賢い合体（研究メモ・題材②）

2026-09-27。題材は `[ss3-blob-merge]`（単純平均が悪い方の親より悪い）。第1段は監査待ち。

## 1. 何が効くのか（原文から）

- **同じ初期値だけでは線形につながらない**: 同じ W0 からデータの順番だけ変えた2体を直線で結ぶと、LeNet 以外は途中の誤差が当てずっぽうまで上がる。早い時点 W_k から分かれた2体なら山（instability）は消える（ResNet-20 は学習の3%から）[1 §3・図2・図3]。ss3 の2体もこれだと読んだが、**実測で外れた**（§3）
- **Task arithmetic / TIES**: τ = θ − θ_init を足し合わせる。単純に足すと値が縮む干渉が起きる。TIES は τ の上位 k%（既定20%）だけ残し、成分ごとに合計の符号を選び、同じ符号の親だけで平均。θ = θ_init + λ·τ_m（既定 λ=1）[2 §3]
- **DARE**: τ を確率 p で捨て、残りを 1/(1−p) 倍する。τ が小さいとき（例: 0.002 以内）に効き、大きいと壊れる [3]。赤子の τ は大きいので向かないと予想（第1段では入れていない）
- **進化的な合体（Sakana AI）**: TIES＋DARE の層ごとの密度と重みを CMA-ES で探す。適応度は**試験とは別の**訓練用サンプル（1069問）で測る [4 §3]。p-kernel では群れが合体のやり方を探す形に写せる

## 2. 脳のどこに入れるか

**第1段**（`st_merge_cohort` は残し、横に足す）
- `st_merge_barrier(A, B, 窓)`: α=0〜1 の5点で線形に混ぜ、損失の山の高さ（[1] の instability）を測る。合体の前に、つながっているかを自分で知る
- `st_merge_guarded(into, peer, init, 検証窓)`: 候補 {α∈0..1 の5点} × {単純、TIES(20%)} を**検証窓**で比べて一番良いものを採る。親そのもの（α=0, 1）も候補なので、検証窓では悪い方の親より悪くならない（進化的な合体の最小の形、総当たり）
- 第2段: 学習率を下げていく計画で山が消えるかを測る（分岐の時点は効かなかった、§3）。第3段: 層ごとの係数を群れで探す [4]

## 3. どう測るか

cert `tests/llm/run_st_merge.sh`（S 段、ss3 と同じ学習。corpus 675B を train 20・検証 4・試験 4 窓に）:
- (A) W0 から分岐した組で山 > 0.05
- (B) 最初は「10% 共有すれば単純平均が悪い方の親以下」を合否にしたが**外れた**ので、測るだけにした
- (C) `st_merge_guarded` の子は、検証窓とは別の試験窓で悪い方の親以下
- 陰性コントロール `-DST_MERGE_PLAIN_ONLY`（α=0.5 だけ）は (C) で赤
- **実測（09-27）**: W0 の組の山は 0.375（単純平均 2.510、親 2.191/2.079）。40周のうち 4/10/20/30 周を共有しても山は 0.278/0.357/0.377/0.301 で消えない。**[1] の処方はこの赤子には効かなかった**。定数の Adam 0.02 のせいかもしれない（未確認。[1] は学習率を下げる計画つき）。検証窓では TIES が最下位（2.685）。守りの合体は α=0＝親 A を選んだ。**悪くはしないが、良い合体はまだ作れていない**
