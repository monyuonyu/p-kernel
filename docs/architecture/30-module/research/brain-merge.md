# 賢い合体（研究メモ・題材②）

2026-09-27 設計。題材は `[ss3-blob-merge]`（S 段の2体を単純平均すると、悪い方の親より悪い）。

## 1. 何が効くのか（原文から）

- **同じ初期値だけでは線形につながらない**: 同じ W0 から、データの順番だけ変えて学習した2体を直線で結ぶと、LeNet 以外は途中の誤差が当てずっぽうの水準まで上がる。学習の早い時点 W_k から分かれた2体なら、その山（instability）は消える（ResNet-20 は学習の3%、VGG-16 は1.5%の時点から）[1 §3・図2・図3]。**ss3 の2体は W0 だけを共有し、Adam 0.02 で40周しているので、この「つながらない」側にいると読める**（未検証）
- **Task arithmetic / TIES**: τ = θ − θ_init を足し合わせる。単純に足すと「値が縮む干渉」が起きる。TIES は τ の大きい上位 k%（既定20%）だけ残し、成分ごとに合計の大きい符号を選び、同じ符号の親だけで平均する。θ = θ_init + λ·τ_m（既定 λ=1）[2 §3]
- **DARE**: τ を確率 p で捨て、残りを 1/(1−p) 倍する。τ が小さいとき（例: 0.002 以内）に効き、大きいと壊れる [3]。赤子の τ は大きいので、そのままでは向かないと予想する
- **進化的な合体（Sakana AI）**: TIES＋DARE の層ごとの密度と重みを CMA-ES で探す。適応度は**試験とは別の**訓練用サンプル（1069問）で測る [4 §3]。p-kernel では「群れが合体のやり方そのものを探す」形に写せる

## 2. 脳のどこに入れるか

`st_merge_cohort` は今の単純平均のまま残し、横に新しい入口を足す。

**第1段**
- `st_merge_barrier(A, B, 窓)`: α=0, 0.25, …, 1 で線形に混ぜ、held の損失の山の高さ（[1] の instability）を測る。合体する前に「この2体はつながっているか」を自分で知る
- `st_merge_guarded(into, peer, init, 検証窓)`: 候補 {α∈0..1 の5点} × {単純、TIES(20%)} を**検証窓**で比べ、一番良いものを採る。α=0 と 1（＝親そのもの）も候補なので、検証窓の上では悪い方の親より悪くならない（進化的な合体のいちばん小さな形。探し方は総当たり）
- 第2段: 分かれる時点を揃える（群れの合体を「前回の合体の結果から分かれた子どうし」に限る。[1] の W_k）。第3段: 層ごとの係数を群れで探す [4]

## 3. どう測るか

cert（tests/llm、S 段、seed 固定、ss3 と同じ corpus と学習）:
- (A) 今の ss3 の組（W0 から分岐）で山の高さ > 0 を再現する（失敗の原因を測る）
- (B) 共有の W_k（全体の 10% を一緒に学習してから分岐）なら山がほぼ 0 で、単純平均も悪い方の親以下
- (C) `st_merge_guarded` の子は、**検証窓とは別の held 窓**で悪い方の親以下
- **陰性コントロール**: `-DST_MERGE_PLAIN_ONLY`（候補を単純平均 α=0.5 だけにする）は (C) で赤（＝今の ss3 の赤を再現）。検証窓と試験窓を同じにするビルドは緑になりやすい＝漏れを見せる対照として記録だけする
- 予想: (A) は山あり、(B) は山がほぼ消える。外れたら書く
