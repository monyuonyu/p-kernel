# 賢い合体（研究メモ・題材②）

2026-09-27。題材は `[ss3-blob-merge]`（単純平均が悪い方の親より悪い）。第1段は master、第2段は測定。

## 1. 何が効くのか（原文から）

- **同じ初期値だけでは線形につながらない**: 同じ W0 からデータの順番だけ変えた2体を直線で結ぶと、途中の誤差が当てずっぽうまで上がる。早い時点 W_k から分かれた2体なら山（instability）は消える（ResNet-20 は学習の3%から。学習率を下げる計画つき）[1 §3・図2・図3]
- **Task arithmetic / TIES**: τ = θ − θ_init を足す。TIES は τ の上位20%だけ残し、成分ごとに合計の符号を選び、同じ符号の親だけで平均 [2 §3]
- **DARE**: τ を確率 p で捨て 1/(1−p) 倍。τ が小さいときだけ効く [3]。赤子の τ は大きいので入れていない
- **進化的な合体（Sakana AI）**: TIES＋DARE の層ごとの係数を CMA-ES で探す。適応度は試験とは別のサンプルで測る [4 §3]

## 2. 脳のどこに入れるか

- 第1段（master）: `st_merge_barrier`（α 5点の山の高さ）、`st_merge_guarded`（α 5点＋TIES を検証窓で比べて採る。親も候補なので悪い方の親より悪くならない）
- 第2段（測定、`tests/llm/student_merge_lr_probe.c`）: 学習率の計画で山が消えるか
- 第3段: 重みの平均をやめ、知識を出力で渡す（蒸留）か、係数を群れで探す [4]

## 3. どう測るか・測った結果

cert `tests/llm/run_st_merge.sh`（corpus 675B を train 20・検証 4・試験 4 窓）: (A) W0 の組で山 > 0.05 (C) 守りの合体の子が試験窓で悪い方の親以下。陰性コントロール `-DST_MERGE_PLAIN_ONLY` は (C) で赤
- 第1段（定数 Adam 0.02）: 山 0.375。4/10/20/30 周共有しても 0.28〜0.38 で消えない。守りの合体は親 A を選んだ＝**安全網であって良い合体ではない**
- 第2段（同じ赤子・同じ窓で計画だけ変える。const は第1段と全桁一致）: W0 の山は linear 0.62・cosine 0.42・step 0.70 と**かえって高い**。共有を増やすと消える（30周共有で 0.03/0.0005/0.0002）が、そのとき学習率は最初の 1〜25%（step・cosine・linear）で、2体はほとんど動いていない（30周共有の |A−B| は 1.4/0.2/0.006＝重み全体の 3.7%/0.5%/0.01%。定数では 16.7＝34% 離れて山 0.30）。山が 0.05 未満になった3組はどれも距離が 1.4 以下で、離れてもつながる組は無かった。**[1] の「早く分かれても平均できる」はこの赤子では再現しない。** 独立に学んだ赤子を重みの平均で合体する道は、ここで閉じる → 第3段へ
- 副産物: 学習率を下げると親そのものが良くなる（試験の損失 const 2.19/2.08 → linear 1.43/1.55）。赤子の学習は今どこも定数の学習率（例: 睡眠の固化は 3e-3、student_shell.c:301）。**別の項目として確かめる**（この小さな corpus だけの話かもしれない）
