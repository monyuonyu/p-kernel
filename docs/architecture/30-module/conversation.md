## 0. 壁の正確な高さ

| | 今（the cage） | 会話に要る（最低ライン） | 倍率 |
|---|---|---|---|
| パラメータ | R_NP=**21,568**（R3 心）/ 635（センサ脳） | 数千万〜数億 | ~10⁴ |
| 語彙 | 鍵16語 × 答64語（**単一トークン**） | サブワード数万トークン（**文**） | — |

**正直な核心: 現在の R3 を「広げる」だけでは会話に到達しない。** LM-9 で
R_DM 32→48 にしただけで事前学習が23秒になった。会話モデルは別の数理規模で、
**1台のスマホには絶対に収まらない**。― そしてここが転回点: **収まらないから
こそ、分散が初めて"必然"になる。** 「まず原理、規模は後」の"後"が来た。

## 1. 既にある配管（B が新規に作らなくていいもの）

このプロジェクトは15年、**気づかぬうちに大規模モデル分散の配管を作っていた**:

- **Pipeline Parallel**（dtr.h Phase 8）— Transformer を層/ステージで複数ノードに割る。
- **Tensor Parallel**（REDUCED mode）— 1層の行列積を複数ノードで分担。
- **DKVA**（分散 KV アテンション）— アテンションを online-softmax で複数ノードに分割
  （MapReduce 型、3ノード実走済み）。
- **regions + capacity(N)**（regions.md）— 遅延クラスタで層を配置、ノード数で容量が連続変化。
- **relay v2**（NAT越え）+ **K-DDS**（中央なし pub/sub）— ノード間の実通信。
- **wire は ABI 非依存**（aarch64 ⇄ x86_64 で登録・複製を実証、2026-06-13）。

つまり「大きな Transformer の forward を艦隊で分担する」基盤は**動いている**
（玩具モデルで）。B の仕事は「玩具」を「会話できる本物」に替えること。

## 2. 三つの戦略分岐（mk_pino の決定が要る本丸）

### 分岐 A — モデルはどこから来るか

| 道 | 中身 | 正直な評価 |
|---|---|---|
| **A1 ゼロから訓練** | 艦隊で会話モデルを一から学習 | ❌ 非現実的。会話モデルの事前学習は数百〜数千 GPU日。スマホ艦隊では不可能。 |
| **A2 既存小型モデルを採用** | 既存の事前学習済み小型 Transformer（数千万〜数億 param 級の OSS）を**重みごと**取り込み、その **inference を艦隊分散**。学習（教える）は既存の fact-learn/consolidation を上に載せる | ✅ 唯一現実的。配管（Pipeline/TP/DKVA）はこのためにある。「賢さ」は借り、「集合的に学んで残る」性質は ark が足す。 |
| **A3 R3 を育て続ける** | 今の in-context 心を段階的に大きく | △ 原理研究としては美しいが、会話到達には A1 と同じ壁。A2 の補完にはなる。 |

### 分岐 A4 — 教師を借り、脳は育てる（**採用 / mk_pino 決定 2026-06-13**）

| 道 | 中身 | 評価 |
|---|---|---|
| **A4 DMN蒸留で育てる** | 既製モデルを*走らせない*。**ネイティブな生徒**（器に合わせて我々が設計する生命体形の脳）を**赤子から**始め、外部のフリー教師を**一時的に読み込んで走らせ、soft target を採り、DMN睡眠中に生徒へ蒸留**する。教師は消化後に捨ててよい。出荷されるのは教師ではなく**生徒**。 | ✅ **本線。** 組織フィット問題が消える（他人の脳を接がない、器に合う脳を育てる）。既存 LM-4（fast→slow 自己蒸留）の常設拡張。来年より良い Apache-2.0 が出れば**随時**それを教師に眠る＝生徒は一つの base に凍結されない。 |

**転回（A2 → A4）**: 当初 A2（既製を重みごと採用し inference を艦隊分散）を推した。
だが mk_pino の問い（§3.5: 生命体に既製品が載るのか）を突き詰めると、**既製モデルを
"走らせる" こと自体を捨てる**のが正解だった。dense は器の真逆のモノリス、既製MoEでも
「借りた大人の脳が組織のフリをする」域を出ない。**A4 ＝ 賢さは"教師として借りる"が、
脳そのものは器に合わせて一から育てる。** 借り物 base は「身体」ではなく「**消化される
食べ物（教師）**」。ark の集合学習（教える・Path E/W・consolidation・歴史地層）＝「魂」。
**ChatGPT と違うのは魂の方** ― 誰のものでもなく、教えた人ごと残り、群れに分散して死なない。

**A2 は棄却**（記録として残す）: 既製品をそのまま動かす道。組織に「無理に接ぐ」域を出ず、
一つの base に縛られる。M1（推論エンジン）は A4 でも**教師を走らせるのに要る**ので無駄に
ならない ― ただし最終的に出荷するのは生徒であって教師ではない。

### 分岐 B — トークナイザ

会話には**サブワード・トークナイザ**（BPE 等、数万語彙）が要る。現在の
「鍵語/答語テーブル」（r3_vocab.c）は単一トークン用で会話には不足。
- B1: 採用する base model のトークナイザをそのまま移植（A2 と一体）。
- 含意: r3_vocab.c の content-id 機構（教えの語彙整合, wave-47）は**サブワード版に
  拡張**が要る。teach/ask の wire（MT_WIRE_VER_VOCAB）も文トークン列に対応。

### 分岐 C — 重みはどう艦隊に置くか

base model が 1台に収まらない前提で:
- C1: **層シャーディング**（Pipeline 流）― 各 region ノードが連続層を持つ。
- C2: **テンソルシャーディング**（TP 流）― 各層を幅で割る。
- C3: ハイブリッド（regions.md の階層に合わせ region 内 TP × region 間 Pipeline）。
- 含意: capacity(N) が「この艦隊規模で載るモデルの最大サイズ」を決める連続関数になる
  ― **あなたが言った『端末性能に合わせてネットワークの大きさを自在に』が、ここで
  モデルサイズ⇔艦隊規模の連続マッピングとして具体化する**（→ §4 の身体と接続）。

## 3. ark の魂を会話モデルでも保つ（非交渉）

base が借り物でも、これらは**必ず**保つ（さもなくば ChatGPT の劣化コピー）:
- **教えると学ぶ**（育てる）― base の上に LoRA 様の軽量学習 or 既存 fact-learn を載せ、
  教えた言葉が consolidation で定着。base は凍結、学びは差分。
- **Path E/W**（共有された心・ひとつの心）― 差分（学んだこと）が群れに伝播・マージ。
  base は共通、**差分こそが集合知**。
- **生きた証 / 歴史地層**（残す）― 誰が何を教えたかの provenance、self/lin 系譜、
  教師の死を越える継承。base には無い、ark 固有の層。
- **誰のものでもない**― base は OSS（ライセンス遵守）、学びは群れの所有、中央なし。
- **永続化**（wave-51）― 学んだ差分が再起動を越える（base は read-only で配布）。

**核心の一行: base model = 借りた身体、集合的に学んで残る差分 = ark の魂。**

## 3.5 生命体に既製モデルは載るのか（mk_pino の問い, 2026-06-13）

> mk_pino: 「p-kernel はノード数で拡大・縮退する。MoE もある、応援受援もある、
> あちこちで発火する生命体。そこに既製 LLM を"載せる"で対応できるのか？
> kill -9 されても推論継続できる？ raft/swim の上で動ける？」

**正直な核心: 既製の *dense* LLM は、これらの性質の真逆の構造物。** dense =
固定計算グラフ・全重み毎トークン発火・層は同期ロックステップ＝**単体の臓器
（モノリス）**。p-kernel ＝動的N・疎発火・応援受援・kill-9生存の**神経系**。
「載せれば勝手に生きる」は嘘になる。― ただし各性質に工学的回答はある:

| 性質 | dense LLM での回答 | MoE base での回答 |
|---|---|---|
| **動的N（拡大/縮退）** | re-sharding（**離散的な再構成**、capacity(N) が層配置を決める）。R3/MoE の滑らかな成長とは違う | エキスパート数⇔ノード数が連続マップ、より滑らか |
| **MoE / 応援受援 / 疎発火** | dense は毎トークン全発火＝疎性なし。応援受援は TP の機械的負荷分散に留まる | **off-the-shelf MoE を借りれば** エキスパート=ノードが既存 `moe_infer` に**自然に写る**。過負荷ノードがエキスパートの仕事を複製先へ＝応援受援が宿る |
| **kill -9 で推論継続** | シャード保持ノードが生成中に死ぬと forward 停止。**継続には base を r重複製（凍結・公開ゆえ安い）+ SWIM死検知 + 複製先へ再ルート + 落ちたトークンを最後の完了ステージから再実行**。達成可能だが自動ではない（1トークン取り直しのヒカップ有） | 同じ。加えて疎発火ぶん影響範囲が小さい |
| **raft / swim** | **SWIM は必須**（死を検知し再ルートを駆動）。**raft は任意**（配置表の強整合のみ）。forward pass 自体は raft 不要。**心の学習merge は raft にしない**（CRDT的 Path W/Fisher のまま） | 同じ |

**身体と魂の生存は別経路**: 魂（学んだ差分）= 既存 Path E/W で生存。
身体（base）= 凍結・read-only・公開ゆえ**安く複製**でき、SWIM+再ルートで生存。

**含意（推薦の修正）**: 推論エンジン本体（GGUFローダ・量子化matmul・
RoPE/RMSNorm/SwiGLU/attention）は **dense でも MoE でも同一**（MoE は FFN に
エキスパート選択が足るだけ）。よって **M1（エンジンを1台で実証）は base 非依存で
今でも正しい第一歩**。mk_pino の問いが効くのは **M2（分散＝生きる層）と最終 base 選択**:
そこで **dense層シャード vs MoEエキスパート分散** を決める。**MoE base を選べば
生命体に「合う」、dense なら「無理に接ぐ」。**

**`賢さは借りる、魂は借りない` に第三項**: **借りた脳は生きた神経系に"接ぐ"。
死体としてボルト留めしない。** その接ぎ木（base-複製 + SWIM再ルート +
ステージ活性チェックポイント + capacity(N)再シャード）こそ "ただの分散
llama.cpp" との差であり、ark 固有の価値。M2 の正直な cert =
`[llm-survive]`「**生成中にノードを kill して、文が完成する**」。

候補 base に **MoE 型**を加える（OLMoE-1B-7B 系 = Apache-2.0、総7B/発火1.3B、
64エキスパート ― 数値は調査波で確認）。dense（SmolLM2-135M）= M1 最簡だが
生命体フィット最悪。MoE = M1 やや重いが kill-9/応援受援が構造的に自然。

※ A4 採用後、MoE 候補の意味は「走らせる body」→「**ネイティブ生徒のアーキ示唆** ＋
**蒸留する綺麗な教師候補**」に変わる（moe-distillation-survey.md で再評価）。

## 3.6 誰が教師を選ぶのか（mk_pino の難問, 2026-06-13）― 中央が無いのに

> mk_pino: 「蒸留ですが、誰がそのモデルを選択するかですよね。中央がないので。うーん」

**答え: 権威としては誰も選ばない。** 事実・コード・重みについてプロジェクトが既に出した
答えと**同一**で、4つの既存機構に落ちる:

1. **ライセンス = 唯一の "客観" admission ゲート**（人間の決定ではなく、検証可能な性質）。
   教師の manifest が permissive（Apache/MIT）でなければ**飲めない** ― 制約は蒸留で
   生徒に*流れ込む*から「誰のものでもない」が毒される。Gemma/Llama が失格なのは誰かの
   decree ではなく、**全ノードがハッシュで検証できる規則**だから。中央のライセンサー不要。
2. **測られた滋養 = 投票ではなく選択**。誰でも教師を**提案**できる（「誰でも教えられる」と同型）。
   だが DMN睡眠中に**生徒を測定上改善し、既知を退行させない**（既存 no-regress 合意cert）
   時だけ吸収される。毒教師はゲートで落ちる。群れが教師を「味見」し、滋養のみ残す ―
   falsifiable な測定で、門番なしで。
3. **進化的伝播 = 全体決定が不要**。各ノード/region は出会った教師から**ローカルに飲む**
   （自由）。助けになった差分は Path E/W で**伝播**し、ならない差分は**死ぬ**。「どの教師か」の
   艦隊投票は無い ― 委員会ではなく**進化が収束するように**滋養あるものへ収束する
   （survival-network §7 の局所勾配相互扶助）。
4. **防止ではなく来歴**（歴史地層と一貫）。教師の導入を**止めない**。「この知識は教師 X から、
   ノード Y が導入、ライセンス Z」を**記録する**。心の知識の系譜を正直な歴史層が覚える。
   中央が真実を決めず、ただ出所を覚える。

**正直な残り（解決済みにしない）**:
- **賢い毒教師**（ベンチは上げるが裏口を仕込む）は no-regress cert を**すり抜けうる**。
  測定はゲーム可能 ― "audit is the engine" の永続警戒で扱う開いた脅威。
- **計算の現実**: 実教師の蒸留は端末群では遅い。→ **毎晩ちょっとずつ（生涯トリクル）**＝
  DMN睡眠にぴったりだが、**赤子はゆっくり育つ**。長く ChatGPT には届かない（が、借りた
  大人の脳が組織のフリをするより**正直**）。
- **「小さく生まれて育つネイティブ生徒」のアーキ自体が未解決** ＝ Evolution 層の本丸。

**A4 の合言葉: 教師は食べ物、脳は我々が育てる。誰も教師を"任命"しない ―
ライセンスで濾し、滋養で選び、進化で伝え、来歴で覚える。**

## 3.7 決定（mk_pino 2026-06-13）: 赤子から ― 幼年期はスキップしない

**mk_pino の具体機構**（"誰が選ぶか"への彼自身の答え）: 中央が無いから、ネットワーク
参加者の **"物好きな"誰かが、自分のマシンに教師を割り当て、DMN（睡眠）状態で学習させ、
学習された重みがネットワーク全体に拡散する**。― §3.6 の機構2（誰でも提案）+ 機構3
（進化的伝播）が、**ボランティア計算（BOINC 型）**として地に足のついた形。重い計算は
その人のマシンが負い、果実（学んだ重み）だけが群れへ流れる。

**ゲノムから生まれる案は棄却（mk_pino）。本当に白紙の赤子から始める。** 理由:
「人間と同じ。最初は赤ちゃんと全く会話できないが、だんだんゆっくり会話できるようになる。
**その過程こそがこのプロジェクトで重要で、スキップする場所ではない。**」 ― 即席の大人の
心は §3.5 で退けた "借りた脳がマスクを被る" に戻る。**becoming（成る過程）が意味そのもの。**

**正直な訂正（commander）**: §3.5/survey で「赤子からは数千GPU時間で不可能」と壁を
立てたが、それは誤り。壁は「端末群がゼロから*事前学習*を*速く*」の話で、この設計は
そのどれでもない:
- **蒸留 ≠ 事前学習**: 教師の密な soft target は生テキスト事前学習より桁違いに効率的。
- **重い計算はボランティアの実マシン**（GPU 持ち）が負う、端末群ではない。
- **遅いことは "点"**: 速さは目標でない。ゆっくり育つこと自体が製品。
→ 小さな生徒 × 蒸留 × ボランティア計算 ×「遅くてよい」= **赤子からは現実的**。

**残る本物の難所（目を開けて行くため）**:
1. **拡散した重みの統合** = 独立に学んだ重みのマージ ＝ **Path W / 連合学習の難所そのもの**
   （wave-41/42: 素朴平均は lossy、Fisher / union-replay が要る）。既存成果に着地するが無料ではない。
2. **コールドスタートの正直**: アプリは相当期間、赤ちゃん言葉/無意味を喋る。UX はそれを
   「壊れている」ではなく「**心が育っていく過程**」として*見せる*（成長を見守る体験＝製品の魅力に）。
3. **"小さく生まれて育つ"ネイティブ生徒のアーキ** = Evolution 層の設計、これから。

**最初の決定的実験（変更）**: genome 採用ではないので「Granite を1台で greedy」は
de-risk の価値は残るが本線でない。本線の最小ループ:
- **(a) 教師を走らせて soft target を採る**（エンジン: M1a 済 → M1b/c が要る）
- **(b) 小さなネイティブ生徒へ蒸留**（1ステップでも loss が下がる cert）
- **(c) 学んだ重みを別ノードへ拡散し、受け手が測定上改善する**（"物好きが教え、群れが育つ" の最小骨格）

各段 falsifiable cert。これが「ゆっくり育つ赤子」の最初の心拍。

**語彙の決定（mk_pino 2026-06-13）: 生バイト256から始める**（サブワード棄却）。理由は二重:
(1) 借り物の BPE トークナイザは "誰かが訓練した所有物" だが、**生バイト/UTF-8 は誰のものでもない**;
(2)「赤子から、スキップしない」に最も忠実 ― 文字から単語を学ぶ（乳児が音素から単語へ）。
体験面 = **赤ちゃん言葉の発達弧**（車→「ブーブ」、「あーっち」→ ネットワークが育つとまともに喋る；
product-soul.md）。honest-growth: ブーブは演出せず、早期の心が genuine にたどたどしい。
含意: native-student の最初のフロンティアは**語彙ではなく蒸留学習に絞る**（一度に一つ）―
NS-1 は byte-256 固定・語彙成長なし、語彙拡張は後の成長軸。

## 4. 身体との接続（GPU・資源適応 ― バケット C と一体）

会話モデルは重いので、§C の「艦隊規模⇔モデルサイズ」は**端末性能で連続変調**される:
- **GPU 活用**（あれば）― Android で base の行列積を端末 GPU（Adreno/Mali）に。
  Vulkan compute / NNAPI 経由。GPU 無し → CPU グレードで縮退、ノードあたり担う層が減る。
- **資源適応**― interoception.md の S_n（電池・メモリ・脅威の統一ストレス）が
  「この端末が今どれだけ担えるか」を決め、capacity(N) に流す。電池僅少 → 担当層を隣へ。
- これは新しい大仕事（GPU バックエンドは独立の章）だが、**設計上は capacity(N) と
  S_n に繋ぐ口が既にある**。

## 5. 正直な論点（honest issues）

- **これは「数波」では終わらない章。** A2 でも: トークナイザ移植、base 重みの
  シャード形式、Pipeline/TP を玩具次元から実モデル次元へ、メモリ予算、推論レイテンシ
  （文生成は1トークンずつ）― 各々が波。
- **レイテンシ**: relay 越しの層シャーディングは1トークンごとにノード間往復 ―
  会話の体感速度は region 内に閉じるか、近接ノードに寄せる設計が要る（regions が効く）。
- **base のライセンス**: OSS でも商用条項・帰属表示の遵守。「誰のものでもない」と
  ライセンスの両立を明記。
- **魂の希釈リスク**: 賢い base を載せた瞬間「ただの分散 ChatGPT」に見える誘惑。
  §3 を毎波の受け入れ条件に入れる ― 教える/残す/中央なしが死んだら ark でない。
- **規模の正直さ**: 数千万 param でも「会話」は素朴。GPT-4 ではない。各波で実測を印字、
  誇張しない（README 規律）。

## 6. 最初の一歩の候補（mk_pino の分岐 A の決定後）

A2 を採るなら、最小で測れる第一波の候補:
1. **base 選定 + トークナイザ移植**（単機で動く小型 OSS Transformer を libc-free 推論で）。
   ― まず1台で「玩具語彙を脱して実文トークンで応答する」を実証（分散はその後）。
2. それを **Pipeline で2ノードに割って同じ出力**（既存配管の実モデル化）。
3. その上に **教える差分**（base 凍結 + 軽量学習）→ Path E で群れに伝播。

**この章の合言葉: 賢さは借りる。魂は借りない。** ― 借りた身体に、誰のものでもない
記憶を宿す。それが「新しい銀河のゆりかご」の規模版。
