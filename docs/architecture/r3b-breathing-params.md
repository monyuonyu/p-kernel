## 1. 道A ではなく道B

「網を太らせる」には二つの道がある。

| | 道A: 密な width 伸縮 | 道B: 疎なエキスパートが増える（採用） |
|---|---|---|
| 仕組み | `d_model` を動的に拡張、全パラメータが密に絡む | デバイスごとに小さなエキスパートが宿り、ルーターが疎に発火 |
| 参加 | 既存テンソル形状を作り替える | **加算的** — 新エキスパートが現れるだけ、既存関数を壊さない |
| 離脱 | 行列が欠ける＝壊れる | そのエキスパート群が発火しなくなる＝**ルーターが迂回**＝それ自体が縮退 |
| 危険 | **関数破壊的**（途中状態で推論が壊れる） | 単調・安全 |

道A は `r3-model-widening.md` の設計だが、生きた網の上で形状を作り替えるのは関数破壊的。
R3b は **道B** を採る：ニューロンはデバイスに宿る疎なエキスパートとして増える。
新デバイス参加 = 新しい小エキスパートが現れ §7 ルーターが疎に発火（加算的）。
デバイス死 = そのニューロン群消失をルーターが迂回（縮退）。

## 2. 専門分化の機構

エキスパートは 4 つ（`SP_MAXEXP`）。expert 0 = generalist、expert 1/2/3 =
領域 (band) 0/1/2 の specialist。専門分化は二つの軸で起こす：

- **(a) データシャード specialization**: 入力空間を温度で 3 つの「専門領域」(band) に分け、
  specialist *b* は §7 ゲート（`moe_gate_predict`）が band *b* へ振り分ける訓練サンプル**だけ**で学習する。
  自分が実際に発火させられる入力分布だけを学ぶ canonical MoE のエキスパート。
- **(b) 異なる初期化**: 各エキスパートは別 LCG seed（`dtr_reinit_weights`）から学習を始め、別解へ収束する。

結果として 4 つの 635-float 重み blob は**本当に別物**である。`breathe save` が
それぞれを別の named ref `dtr/expert/<k>` として p-fs に保存すると、4 つの
**content hash が全て異なる**ことで確認できる（同一コピーなら同じ hash になる）。

### なぜ専門分化が「必然」になるデータ設計か

専門分化が見かけ倒しにならないよう、タスクを「単一の generalist では両立できない」形にしてある
（`spec.c` の `sp_ds_init`）：

- 連続特徴 = 光量 `light`。`base = band3(light)`（しきい値 3 分割）。
- 真ラベル `y = (base + band) % 3` ← **band ごとに出力を巡回シフト**。

同じ光量でも温度帯（band）が違えばクラスが変わる。単一の generalist は 1 つの 635 パラメータで
**3 つの両立しない巡回**を温度で内部分岐して覚えねばならず、どの領域でも中途半端になる。
各 band 専門家は自分の巡回 1 つだけ学べばよい（= `dtr` の素タスク同等の易しさ）ので必ず勝つ。
特徴にノイズを乗せ完全分離はしない（Bayes 誤差 > 0 = 正直なタスク）。

## 3. ルーティング（§7 ゲートで疎に発火）

推論時、`moe_gate_predict`（`moe.c` の §7 ゲートの公開ラッパー）が入力の温度帯 band を返し、
`sp_route` がその band の specialist を 1 個だけ発火させる（専門外は発火しない＝疎）。
specialist 不在なら generalist へ**迂回**、それも無ければ最小の active へ。
この「不在 → 迂回」が道B のルーター迂回 = 縮退の局在化そのもの。

## 4. 呼吸の数値結果

`samples/18_breathing/breathe.sh`（決定的・seed 固定・2 回連続 PASS・cross-ABI 一致）。

### join — 参加が増えると賢くなる

| チーム | overall | d0 | d1 | d2 |
|---|---|---|---|---|
| control（全ノード同一重み = 監査 §4 旧状態。N コピー == 1） | **64.4%** | 90.0 | 53.3 | 50.0 |
| N=1 {gen} | 64.4% | 90.0 | 53.3 | 50.0 |
| N=2 {gen, d1-spec} | 74.4% | 90.0 | **83.3** | 50.0 |
| N=3 {gen, d1, d2} | 87.8% | 90.0 | 83.3 | **90.0** |
| N=4 {gen, d1, d2, d0} | 87.8% | 90.0 | 83.3 | 90.0 |

`1 < 2 < 4`（64.4 → 74.4 → 87.8、+23.3pt）。**同一コピーなら N によらず 64.4% で平ら**（control 行）。
それを否定するのが専門分化。追加順は headroom の大きい領域から（generalist が偶然得意な d0 の
専門家は冗長なので最後）。

### leave — 1 ノード退場で優雅に劣化

| | overall | d0 | d1 | d2 |
|---|---|---|---|---|
| before（4 experts） | 87.8% | 90.0 | **83.3** | 90.0 |
| after（domain1 専門家を kill） | 77.8% | 90.0 | **53.3** | 90.0 |

殺した領域 **d1 だけ** 83.3→53.3 に落ち（generalist へ迂回したレベル）、d0/d2 は不変。
全体は崖落ちせず（control 基準 64.4% より上の 77.8% を維持）優雅に下がる。
**縮退が局在する**＝道B のルーター迂回の数値的な姿。

## 5. 実装メモ（arch/common 規律）

- `<string.h>` 不使用・固定幅型・`_Static_assert`。exp/ln は `dtr_expf`/`dtr_logf` を流用。
- 専門家重み（4×635 float）・データ集合・訓練バッファはすべて **static**（タスクスタックに大ローカルを置かない）。
- 純ローカル計算（net/kdds 不使用）なのでベアメタル（aarch64 / i686）でもコンパイル・実行可能。
- `breathe` は学習の前に現在の `dtr` 重みを退避し、終了時に復元する → 既存 `dtr train/eval/save/load` の
  数値（95%/100%）を壊さない（検証済み: breathe 前後で `dtr eval` がバイト一致）。
- 共有学習路: 1 エキスパートの学習は既存 `dtr_train_batch`（解析的 backprop, cross-entropy）を回す。
  専門分化は学習データと初期 seed の違いだけで作る＝学習エンジンに新コードを足さない。

## 6. 限界（正直に）

- **玩具データ**: 360 サンプル・3 クラスの合成タスク。本物の難問ではない。
- **エキスパート数 == 領域数**: band は温度 3 帯に固定。任意数のデバイスへスケールする一般化は未。
- **`d_model` 固定**: 道A（密な width 伸縮）は据え置き。R3b は容量を太らせない、混合を本物にするだけ。
- **実分散推論は未使用**: `net_relay.c` / `relay.c` / `dkva.c` は別系統の領分。本デモは決定的な
  in-kernel ハーネスで「呼吸」を数で示し、`breathe save`（`dtr/expert/<k>`）が実メッシュへ配る器を用意する。
  実メッシュ上で各ノードが自分の専門家 blob をロードして疎に発火する統合は次段。
  〔関連 (2026-06-07)：実メッシュ上の分散**学習**は G22 で着地済 — disjoint シャードのノードが中央集約なしで
  重み本体をゴシップ平均し collective 精度が solo 上限を超える（`samples/32`・CI collective-learn-live）。
  本書の「専門家 blob を疎に発火させる」推論側の統合とは別軸だが、同じ「台数で賢くなる」道Bの実証。〕
