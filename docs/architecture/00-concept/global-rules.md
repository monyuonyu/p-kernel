# 全体の決まり（8つ）

2026-09-28。[ROADMAP.md](../ROADMAP.md) の「全体の決まり」を、今のコードと結びつけて書いたもの。以後の設計と試験は、これに従う。破る変更は、先にこの文書を変える。

## 1. 合体は3種類。混ぜない
| 種類 | 何を守るか | 今のコード |
|---|---|---|
| 重み | 振る舞いを近づける | `gl_merge` / `gl_merge_w`（gossip_learn.c）、赤子は `st_merge_guarded` |
| 記憶 | 経験を失わない | エングラムの共有と睡眠での再生（lm_consolidate.c） |
| 知識 | 何を知っているか | 事実の書き換え（LM-12、r3_incontext.c） |

重みの平均で知識の食い違いを解決したことにしない。逆も同じ。

## 2. 履歴と今の信念を分ける
直された古い事実は、今の答えからは外すが、履歴からは消さない。「最後に来た方が勝ち」は今の答えを選ぶ規則としてだけ使い、負けた方・出どころ・証拠も残す（ROADMAP 1-3）。

## 3. 「1つの心」の判定は3つ
重みが同じことでは判定しない。(a) 同じ事実を知っている（知識）(b) 同じ問いに同じ答え（振る舞い）(c) 同じ経歴をたどれる（系譜、`self/lin`）。試験はどれを見たかを名前に書く。

## 4. p-fs の合体と知識の合体は別もの
p-fs（pfs_dag.c）は消えない履歴の置き場で、参照は manifest の seq で決める（LWW）。どれを今の信念にするかは心の側が決める。p-fs の LWW を信念の規則として流用しない。

## 5. AI が自分で変えてよいもの・いけないもの
- 変えてよい: 重み、知識、候補のコード（提案まで）
- 勝手に変えてはいけない: 権限の規則、署名の信頼の根、巻き戻しの仕組み、見張り役、自分の権限の範囲、良心の床（conscience.c、締める方向にしか変えられない）
- 信頼の根は AI の外（人間と決まり）に置く。新しい自己改変の口を作るときは、どちらに入るかを設計メモに書く

## 6. 署名は「誰が作ったか」
署名（ed25519、sign.c）が示すのは作り手で、相手が誰であるかや中身が正しいことではない。改ざんが分かる（tamper-evident）と、改ざんできない（tamper-proof）を混ぜて書かない。

## 7. 確かめ方の強さを勝手に上げない
印は [live]（複数プロセス、kill を含む）・[in-proc]（1プロセス）・設計 の3つ（README）。部品が [live] でも、つないだ全体は、つないだ全体を確かめるまで [live] と書かない。測っていないプラットフォームを「全部で動く」に含めない。

## 8. 試験は壊したら赤くなるまで示す
新しい試験やゲートは、わざと壊した版（陰性コントロール）で狙った項目が赤になることを示すまで「効く」と言わない。緑だけの結果は「なぜ動くかが分かった」ことにならない。
