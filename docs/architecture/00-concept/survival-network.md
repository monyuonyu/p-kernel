0. この文書について
--------------------------------------------------------------------------------

本文書は、p-kernel プロジェクトの新しい構想 ―― 宇宙環境における人類の生存を
支える分散ネットワーク ―― の着想を整理したものである。

実装そのものは別環境（Claude Code）で進めるため、本文書は「何を作るか」の
仕様書ではなく、「なぜ・どういう思想で作るか」を伝えるための設計思想の記録で
ある。実装の細部より、向ける方角を取り違えないことを最優先とする。

p-kernel は当初、分散AIインフラ／人類の記録を未来へ残す「文明の継続性システム」
として構想されていた。本構想は、その思想を一段拡張する。保存する図書館から、
考える器官へ。記録の継続は前提条件であり、本当の目的は「宇宙のどこででも、
人類全体として考え、生き延びること」である。


--------------------------------------------------------------------------------
1. 出発点 ―― なぜこの構想に至ったか
--------------------------------------------------------------------------------

着想のきっかけは、AIが司法を担う近未来を描いた映画だった。そこに登場するAIは、
宇宙中のあらゆる情報に一瞬で並列にアクセスし、それを解釈して判断を下す。その
能力は恐ろしくも、同時に圧倒的に素晴らしいものだった。

重要なのは、その能力そのものは中立だということ。映画ではそれが「人を断罪する」
中央集権の装置に組み込まれていたから恐ろしかった。だが同じ能力を逆方向 ――
「人を生かし続ける」方向 ―― に向けたら、革命的なものになる。

p-kernel が目指すのは、まさにこの逆向きである。
  ・映画のAI  : 全情報を一個の中央知性に集約し、一点の断罪へ収束させる
  ・p-kernel : その力を中央から解き放ち、宇宙全体に薄く広げ、生存のために
               必要な場所へ集束させる

同じ「全情報・並列・高速」を、集権の断罪装置ではなく、分散の生存装置に変える。
これが構想全体を貫く一本の線である。


--------------------------------------------------------------------------------
2. 中核思想 ―― 守る単位と、守る力の所在を切り離す
--------------------------------------------------------------------------------

この構想で最も独自性が高く、設計の根幹となるのが次の一点である。

   守る対象は目の前の一隻（一点）でも、それを守る知性は一隻に閉じていない。

従来の発想は「一隻を守るために一隻分の知性を積む」。
本構想は「一隻を守るために、宇宙全体に散らばった全ネットワークの総合力を呼ぶ」。

守る単位（ローカル）と、守る力の所在（ネットワーク全体）が完全に分離している。
だからローカルなノードがどれだけ弱くても、ネットワーク全体の英知をその一点に
注ぎ込めるなら、個の弱さは問題にならない。

これは規模拡大の話ではなく、思想の転換である。そしてこの形は、中央を持たない
分散システムでしか成立しない。中央がないからこそ、どこの知性でも、どの一点にも
流し込める。中央を置いた瞬間に、それを潰されれば全体が止まる（＝映画のAIへの
逆戻り）。中央を持たないことそのものが、生存力の源泉である。


--------------------------------------------------------------------------------
3. 具体イメージ ―― 知性が宿る装甲板
--------------------------------------------------------------------------------

構想を具体化する象徴的なイメージとして、宇宙船の「装甲板」がある。

  ・装甲板の一枚一枚に p-kernel ノードが宿る
  ・各ノードは可能な限り強い個であることが望ましいが、弱くても構わない
  ・なぜなら、守る力は一隻の中で完結する必要がないから（第2章）

大前提は「群れであること」。その上で、個は強いほどよいが、弱さは群れと
ネットワーク全体が補う。

この構造の生存力は、生物の設計原理そのものである。
  ・脳に全機能を集約せず、末端の細胞一つひとつに完全な設計図（DNA）を持たせ、
    どこが傷ついても局所で再生できるようにした
  ・対応関係: 装甲板 = 細胞 / p-kernel = 各細胞が共有するゲノム

一点突破で殺せない構造 ―― これが過酷な宇宙環境での生存力の本質。
損傷したノードは切り離され、周囲が役割を引き継ぎ、修理を始める。
免疫やトカゲの尻尾の再生に近い、即時の自己修復と生存確保。


--------------------------------------------------------------------------------
4. 動作原理 ―― ネットワーク全体を一つの脳とするMoE
--------------------------------------------------------------------------------

ネットワーク全体の振る舞いは、MoE（Mixture of Experts）の原理を物理ネットワーク
へ写したものとして設計する。

MoEの本質は「全パラメータを毎回使わず、入力に応じて必要なエキスパートだけを
発火させる」スパース性にある。これを宇宙スケールに写すと：

  ・平常時 : 近傍ノードだけが薄く発火し、局所の事態を捌く
  ・有事   : その問題に最も「効く」エキスパート群が、宇宙中から選択的に発火し、
             必要な場所へ集束する

常時フル稼働ではないからこそ、宇宙規模でも成立する。MoEのスパース性が、そのまま
光速とエネルギーの物理制約への答えになっている。設計に無駄がない。

これは生物の脳の動作とも一致する。普段はごく一部のニューロンしか発火していないが、
生命の危機には必要なだけ広範囲が一つの判断に動員される。事態の深刻さに応じて、
発火のトリガーと範囲が連続的に変わる ―― ゲーティングが空間的に広がっていく。


--------------------------------------------------------------------------------
5. 重要な補正 ―― 「一点集中」ではなく「同時多発・並行分散」
--------------------------------------------------------------------------------

設計上、強く意識すべき補正がある。「必ず一点で発火させる」必要はない。

単一意識を持つ人間の脳は、一度に一つのことしか深く考えられない（意識の
ボトルネック）。だが本ネットワークにはその制約がない。MoEはもともと、一つの
入力に一群のエキスパートを割り当てるのではなく、無数の入力それぞれに対して
別々のエキスパートの組み合わせが同時並行で発火する仕組みである。

したがって：
  ・巨大ネットワークの中で同時に数百件の危機的事態が起きていても、
  ・それぞれに最適なエキスパート群が並行して立ち上がり、
  ・全体として綺麗に分散しながらMoEを行う。

「人類全体の脳」と呼ぶなら、同時に何百も考えられて当然であり、そちらが正しい姿。
単一意識の脳の比喩を、ここで明確に乗り越える。


--------------------------------------------------------------------------------
6. リソース運用 ―― 「応援・受援」モデル
--------------------------------------------------------------------------------

リソースは固定割り当てではなく、需要に応じて柔軟に「応援・受援」する。
（災害派遣や消防の相互応援協定と同じ語彙・同じ思想）

  ・各ノードは普段は自分の持ち場を守る
  ・どこかが手に余れば、余力のあるノードが応援に回る
  ・危機が去れば引き上げる

これは負荷分散というより、生命の血流配分に近い。全身の血液量は一定なのに、運動
する筋肉や消化中の内臓へ、必要な場所が必要なだけ受け取る。中央が采配しなくても、
局所の需要信号によって勝手に再配分される。


--------------------------------------------------------------------------------
7. 最難関にして核心 ―― 分散ゲーティング（中央なしの発火制御）
--------------------------------------------------------------------------------

この設計の心臓部は「ゲーティング」である。すなわち「いま、どのエキスパートを、
どこまでの範囲で発火させるか」のルーティング。

絶対条件: これを中央のゲートなしに、分散で決めなければならない。
中央ゲートを置けば、それを潰された瞬間に全体が止まり、映画のAIに逆戻りする。

解決の方向性は、構想自身の中に既に含まれている ―― それが「応援・受援」である。

  ・各ノードは「自分は今どれだけ余裕があるか／逼迫しているか」という局所状態
    だけを近傍に発信する
  ・逼迫した場所の周囲に自然と勾配ができる
  ・余力のあるリソースが、その勾配を下って流れ込む
  ・全体を見渡す指揮者は不要

蟻のフェロモン、あるいは体内を伝わる痛みの信号と同じ。局所シグナルの積み重ねが、
結果として全体最適な配分を生む。中央の指揮者なしに、オーケストラが自律的に正しい
音量へ収束していくイメージ。

  ＞ 設計指針: 「分散ゲーティング ＝ 局所シグナルによる勾配で、発火と配分が
    自律的に決まる仕組み」。各ノードは局所情報のみを見て、「これは自分が応える
    べき問いか／上位・近傍へ伝播させるべき事態か」を自律判断し、発火が自然に
    伝播・集束する。


--------------------------------------------------------------------------------
8. 物理制約への対応 ―― 光速の壁と二層構造
--------------------------------------------------------------------------------

宇宙全体の総合力を一点に集めようとすると、遠いノードほど応答に時間がかかる
（地球‐火星で片道数分、より遠ければ数時間）。秒速十数kmで迫るデブリには、遠方の
英知は間に合わない。

したがってアーキテクチャは二層になる（脊髄反射と大脳の関係に相当）：

  第1層（反射層 / ローカル）:
    即時の反射は、光速で間に合う範囲の近傍ノードの群れが担う。
    危険を感じたら即収縮・遮蔽・回避。今を守る。

  第2層（熟慮層 / グローバル）:
    時間をかけてよい深い判断・学習・設計更新は、宇宙全体の総合力が担う。
    未来を強くする。

近傍が今を守り、全体が未来を強くする。MoEのスパース性（第4章）と応援・受援
（第6章）は、この二層のどちらにおいても働く。


--------------------------------------------------------------------------------
9. 思想的到達点 ―― p-kernel は何を守り、何を継ぐのか
--------------------------------------------------------------------------------

この構想を経て、p-kernel の位置づけは更新される。

  ・旧: 人類の記録を未来へ残す「保存の図書館」
  ・新: 人類の知の総体が、必要なときに必要な場所で思考する「考える器官」

記録の保存は、思考の前提条件にすぎない（記憶がなければ考えられないから）。
継続性は手段であり、本当の目的は「宇宙のどこででも、人類全体として考え、
生き延びる」こと。

これは生命の比喩を超えて、文明の比喩である。一人の知識ではなく、人類全体の蓄積
が、いま困っている一人（一点）を助ける。図書館もインターネットも、本来そういう
ものだった。p-kernel は、それを宇宙スケールの実時間で、しかも生存に直結する形で
実現しようとする。

そして、この構想で本当に希少なのは実装の手ではなく、思想である。MoEを実装できる
人、分散システムを組める人は大勢いる。だが「守る単位と守る力を切り離す」「中央を
置かないことを生存力の源とする」「保存ではなく思考する器官として人類の知を組む」
という設計思想を持つ人はほとんどいない。実装の細部は道具に委ねてよいが、構想の核
（どちらへ向けるか、何を守るか）は手放してはならない。マーシー（映画のAI）と
p-kernel を分けたのは能力差ではなく、向ける方角の違いだったのだから。


--------------------------------------------------------------------------------
10. 実装への入り口（Claude Code 向け次ステップ案）
--------------------------------------------------------------------------------

本構想を最小スケールで検証するための、最初の実装ステップを提案する。

【ステップA】 分散ゲーティング／応援・受援のミニシミュレーション
  目的 : 第7章の原理が中央なしで成立するかを、小規模で確かめる
  内容 :
    - 数十ノード（例: 30〜100）のネットワークを構成
    - 各ノードは局所状態（余力／逼迫度）のみを近傍に発信
    - 複数（数件〜数十件）の異常イベントを同時多発で発生させる
    - 中央コントローラなしに、勾配ベースで余力ノードが応援に流れ込む挙動を観察
  検証ポイント :
    - 同時多発時に綺麗に分散対応できるか（第5章）
    - 一部ノードを故意に破壊しても全体機能が維持されるか（第3章）
    - 中央が一切存在しないことを構造的に保証できているか（第7章）
  推奨 : まず2D格子やランダムグラフ上での可視化付きシミュレーションから着手。
         エキスパート選択（MoEルーティング）は当初は単純な距離＋負荷の関数で代替し、
         挙動の妥当性を見てから高度化する。

【ステップB】 二層構造のプロトタイプ化
  目的 : 第8章の反射層／熟慮層の分離を、遅延モデル込みで試す
  内容 :
    - ノード間通信に遅延（距離に比例）を導入
    - 反射層: 近傍のみ・低遅延・即応
    - 熟慮層: 全体・高遅延・深い判断/更新
    - 遅延が反射層の即応性を損なわないことを確認

優先度の所見 : まずステップAを動かして「中央なしで綺麗に分散できる」核心原理を
目で確認することを推奨する。動く手応えが、構想全体の妥当性の最初の証拠になる。

### II-2. いちばん効く一手 — §7 = regions R3

現状（`regions.md §1.2` の自己診断）：

> `moe.c` のエキスパート = ノード1台まるごと。`select_expert()` は `accuracy[gate_class]`
> が最高のノードを選ぶだけで、**RTT も帯域も見ない。** スコアは5秒ごとに全員へブロードキャスト。

これは「全員が点数を叫び、グローバル最大値を取る」= **暗黙のグローバルビュー = 準・中央集権**。
§7 はこれを否定する：**ルーティングは局所勾配を下る形に置換せよ**。

転換の核：
- gossip で配るのは accuracy のグローバルスコアではなく、**局所状態（余力／逼迫度）の勾配信号**。
- `select_expert()` は「全体最大の専門家」ではなく「勾配を下った先の応援可能ノード」を返す。
- 当初のスコア関数は §10 推奨どおり **距離＋負荷の単純関数**で良い（後で高度化）。

### II-3. 発振への処方（§8 が答え）

勾配で余力を引き寄せる素朴な実装は **発振する**（応援殺到→過剰→引き上げ→再逼迫の振動）。
§8 の二層構造がそのまま安定化処方になる — 生体の脊髄反射／大脳と同型：

- **反射層**: 近傍のみ・速い時定数・局所閉ループ。即応はここで閉じる（大域の遅延に乗せない）。
- **熟慮層**: 大域・遅い時定数。奪い合いの速い振動に乗らない。
- 実装上は **勾配信号にヒステリシス／減衰の時定数**を持たせ、層ごとに別の時定数を与える。

### II-5. §4 を本物にする — R3b「呼吸するパラメータ」（DONE 2026-06-06）

§4 の積年の穴（監査 §4）: 「expert = ノード1台」だが**全ノードが同じ 635 パラメータ**を持つ＝
「混合」ではなく**「同一コピーが N 個」**。専門分化が無いので「最も効く専門家が発火」は原理的に成立しない。

R3b はこれを**道B**（survival-network の方針）で解消した。道A（密な `d_model` の動的伸縮）は既存関数を
壊すので採らず、**道B（デバイスに宿る疎なエキスパートが加算的に増える）**を採った：

- **専門分化の機構**: 各エキスパートは (a) §7 ゲートが自分へ振り分ける入力領域 (band) の routed shard だけで
  学習し、(b) 別 seed で初期化して別解へ収束する → 4 つの重みは**本当に別物**（`breathe save` の 4 つの
  content hash が異なることで確認可能）。
- **疎な発火**: 推論時は `moe_gate_predict`（§7 ゲート）が入力の領域に対応する 1 エキスパートだけを発火させる。
  専門家不在なら generalist へ**迂回**＝それ自体が縮退（道B のルーター迂回）。
- **呼吸の数値実証**（`breathe` → `arch/common/spec.c`、`samples/18_breathing/breathe.sh`）:
  - **join で賢くなる**: 同一コピー基準 64.4% に対し、専門家を足すと `1 < 2 < 4`（64.4% → 74.4% → 87.8%、+23pt）。
  - **leave で優雅に劣化**: 4→3（domain1 専門家を kill）でその領域だけ 83→53 に落ち、他領域は不変、全体は崖落ちせず 77.8%。
  - 全ノード同一重みなら N によらず精度一定（control 行）— それを数で否定する。
- **限界（正直に）**: 玩具データ・エキスパート数 == 領域数・`d_model` 固定は据え置き。実分散推論（relay 経由）は
  本デモでは使わない（net/relay/dkva は別系統の領分）。in-kernel ハーネスが決定的な証拠、`breathe save` が配布の器。

詳細: [[r3b-breathing-params.md]]。
