## このロードマップの考え方

レビューの一番大事な指摘は、**次の勝負は新しい器官を増やすことではなく、すでにある器官を1つの流れとしてつなぐこと**（§36・§41・§78）です。

目指す流れ（§33・§75）：

```
経験 → 記憶（エングラム）→ 知識 → 睡眠での定着 → 重み → 群れ
 → 評価 → 実験 → 一部で試す（カナリア）→ 採用 / 巻き戻し → 経歴（self/lin）→ 次の経験
```

そのために、次の順で進めます。

- **段階 0**：土台を固める
- **段階 1**：1つの心（群れの記憶と知識をつなぐ）
- **段階 2**：安全な自己進化
- **段階 3**：群れとしての同一性と長期の生存
- **段階 4**：もっと大きな知能

段階は「前が全部終わってから次」ではありません。各段階の先頭から順に手をつけ、同時に研究と並行の仕事も回します（下の「回し方」）。

## 全体の決まり（最初に文書にする）

作業に入る前に、次の決まりを短い設計メモにします。以後の作業は、すべてこれに従います。

状態：設計メモ [00-concept/global-rules.md](00-concept/global-rules.md) を書いた（2026-09-28、監査-17 PASS）。

1. **合体は3種類に分ける**（§45）
   - 重みの合体（`gl_merge` / `gl_merge_w`）：振る舞いを近づける
   - 記憶の合体（エングラムの共有と睡眠での再生）：経験を失わない
   - 知識の合体（事実・出どころ・直した履歴・矛盾）：何を知っているかを意味でまとめる
2. **履歴と今の信念を分ける**（§47・§48）。直した事実の古い方は、今の答えからは外すが、履歴からは消さない。「最後に来た方が勝ち」は今の答えを選ぶ規則として残し、負けた方と証拠も記録する。
3. **「1つの心」は重みが同じことではない**（§14・§76.4）。同じ事実を知っている（知識）・同じ問いに同じ答え（振る舞い）・同じ経歴をたどれる（系譜）の3つで判定する。
4. **p-fs の合体と知識の合体は別もの**（§50）。p-fs は消えない履歴の置き場、どれを今の信念にするかは心の側が決める。
5. **AI が自分で変えてよいもの・いけないもの**（§69・§70・§76.7）
   - 変えてよい：重み、知識、候補のコード（提案まで）
   - 勝手に変えてはいけない：権限の規則、署名の信頼の根、巻き戻しの仕組み、見張り役（supervisor）、自分の権限の範囲
   - 信頼の根は AI の外（人間と決まり）に置く
6. **署名は「誰が作ったか」であって「誰であるか」ではない**（§8）。改ざんが**分かる**（tamper-evident）と、改ざん**できない**（tamper-proof）を混ぜない（§7）。
7. **確かめ方の強さを勝手に上げない**（§76.12）。部品が [live] でも、つないだ全体は、つないだ全体として確かめるまで [live] と書かない。
8. **試験は「壊したら赤くなる」ことまで示す**（§60・§71）。緑だけでは「なぜ動くか分かっている」ことにならない。

## 回し方

- 夜間開発の計画役は、毎週の回を次のように配分します：**段階の項目（段階 0 → 1 → 2 → 3 の先頭から）が半分ほど、研究が4分の1ほど、並行の仕事が残り**。
- 1つの項目は小さく切ります（レビュー §76.11 の PR-1〜PR-7 の大きさ）。設計メモは2000字まで、作ったら必ず試験と「壊したら赤」まで。
- 週のまとめでは、このロードマップのどこまで進んだかを報告します。
