# p-kernel

**让 AI 不会死去的操作系统**——一个从零编写的研究用内核。

设想是：AI 不再只住在某一家公司的数据中心里，而是分散在大量普通设备上（电脑、手机、小型开发板），只要其中任意一台还在运行，整体就不会停止。p-kernel 从内核（操作系统的最底层）开始，构建这样一个"不属于任何人的 AI 的家"。

本 README 会把**现在能运行的、正在设计的、以及仅是构想的**明确区分开。如有言过其实之处，那就是 bug，会被修正。尚未解决的问题统一公开在 [gap-ledger](docs/architecture/gap-ledger.md)。

- 各功能的详细数据与经过（日文）：[docs/architecture/features-detail.md](docs/architecture/features-detail.md)

## p-kernel 是什么

如今的 AI 只能运行在特定公司的服务器里。那家公司一旦关停，这个 AI 就消失了。p-kernel 反过来思考：如果 AI 分散住在许多机器上，是不是就不存在一个能把它抹除的地方了？

用研究的语言来说，p-kernel 探索的是**面向分布式人工生命的基础（Artificial Life substrate）**。这并不是说已经创造出了生命或意识，而是在实验中构建这样一个基础：小小的心智能够跨越故障持续存在、彼此共享记忆与知识，并在明确的安全边界内进化。

为此，我们按以下原则构建：

- **不设中心。** 没有中心服务器、名录或协调者。设备之间互相监视以判断谁还活着（SWIM），任何一台消失，其余设备照常运行。
- **从内核开始构建。** 核心是符合 IEEE 2050-2018 的实时内核 μT-Kernel 3.0。以群体方式运行的能力作为内核功能来实现，而不是在应用层事后添加。
- **搭载一个虽小但真正会学习的大脑。** 从"学到东西"到"在空闲时（睡眠）固化进权重"的路径确实在运行，并且已经复现了遗忘问题，也测量了治疗效果。不过规模目前还只是玩具级别。
- **凡是写着"能运行"的，都由自动化测试检验。** GitHub Actions 的 CI（截至 2026-09-27 共 49 个任务）每次都会检查。

### 五个层次

把整个系统比作生物，分成五层来思考。

| 层 | 作用 | 目前的内容 |
|---|---|---|
| 身体（Body） | 硬件、输入输出、不会丢失的存储 | 抗断电的文件系统 ARK、分布式存储 p-fs |
| 大脑（Brain） | 在一台设备内思考和学习 | 记忆词语关联的小型大脑（约 21,568 个参数）、从白纸开始成长的语言模型 |
| 自我（Self） | 跨越机器延续的"自我" | 用哈希串联起来的经历记录（self/lin） |
| 群体（Collective） | 许多设备作为一个整体运行 | SWIM、邻近设备组成的群组（region）、内核内的发布/订阅（K-DDS）、群体学习 |
| 进化（Evolution） | 运行中改造自身 | 仍处于最初阶段；先行构建安全机制（隔离与签名） |

## "能运行"的标注方式

本 README 中的"能运行"都附有证据强度。

- **CI**：每次都在 GitHub Actions 中检查。也有失败（红色）的任务，最新结果请以 Actions 页面为准。
- **[live]**：实际启动多个独立进程、并包括中途 kill 进程在内确认过的。最强的证据。
- **[in-proc]**：在单个进程内运行真实代码确认过的。不包括真实的进程死亡。

未列在"现在能运行的"之中的，都不声称能运行。

## 现在能运行的

### 内核与目标平台

- 核心是 **μT-Kernel 3.0**，于 2026 年 7 月从 micro T-Kernel 2.0 迁移而来（`kernel/mtkernel3/`）。
- 同一套源码可构建以下五个目标：

| 目标 | 状态 |
|---|---|
| 裸机 x86-64（QEMU） | 启动到 shell |
| 裸机 AArch64（QEMU virt） | 启动到 shell。附带 Raspberry Pi 3 网络启动步骤（实机的 SD 卡尚未支持） |
| Linux 上的进程（aarch64，`boot/linux`） | 启动到 shell。Android 应用的基础 |
| Linux 上的进程（x86_64，`boot/linux_x86_64`） | 启动到 shell |
| Windows x86_64（`boot/windows/x86_64`） | 可构建 `.exe`（CI 已确认）。尚未在实机上确认能否启动 |

- **内核与上层之间约定的测试**（2026-09）：用 62 项检查上层使用的 `tk_*` 调用是否按规范运行（任务、信号量、事件标志、互斥量、时间——包括错误码和边界值）。期望值已与 μT-Kernel 3.0 规范核对。每次都会确认 5 个故意破坏的内核构建会让测试变红。在 Linux x86_64、裸机 x86、裸机 AArch64 上运行（`arch/common/tk_conform.c`）。
- 多核支持的第一阶段已经加入（CI `smp-autodetect`）。

### 连接

- 同一局域网内的设备无需中继即可互相发现并连接 [live]。
- NAT 内的设备通过中继（`relay/`）互相通信。通信使用 HMAC-SHA256 认证并防御重放（CI `relay-tests`）。不加密。中继宕机后网络仍然存在，任何人都可以自己搭建中继。
- 邻近的设备组成群组（region），繁重的交互在群组内完成。
- 每台设备都在自己内部持有整个网络的视图（设备、群组、存活与否）——即 shell 的 `world` 命令。
- UDP 不通时自动切换到 TCP（CI `connect-anywhere-certs`）。
- aarch64 和 x86_64 设备可以加入同一个群体。
- 群体上限为 64 台。实际运行确认到 32 台 [live]；64 台在单个进程内检查过 [in-proc]。

### 不会停止

- 在分担推理的过程中 kill 掉一台设备，剩下的设备会完成推理，并自行报告"正以 k/n 台设备降级运行"（CI `survival-loop`）[live]。
- 指定要保护的对象后，群体会复制它以保住它。kill 掉所属设备，它仍在相邻设备上存活（CI `protect-loop-live` 等）[live]。
- 一台空白的新设备，可以凭网络上的权重、代码和角色成长为完整的成员。
- 资源持续不足时，设备进入"休眠"并停止繁重工作，群体也会避免给它分配任务（CI 中的三项测试）[in-proc]。

### 记忆

- **p-fs**：以内容哈希为地址的分布式存储。相同内容自然合并为一份，篡改会立即表现为地址不一致。
- **ARK**：抗断电的文件系统。在反复、机械地于写入中途断电并破坏数据的测试中（CI `ark-crash-fuzzer`），从未返回过损坏的数据。
- 设备 ID、经历记录和学到的权重在重启后依然保留（Android 上也是）。

### 群体学习

- 每台设备只持有部分数据，在没有中心服务器的情况下混合彼此的权重，结果优于任何一台单独学习。学习过程中被 kill 也能坚持（CI `collective-learn-live`）[live]。
- 两到三台设备可以分担同一个 Transformer 前向计算。

### 会学习的大脑（词语关联）

约 21,568 个参数的小型大脑，学习词语之间的关联。

- 用 `mind teach sky blue` 教它，`mind ask sky` 就会回答 "blue"。
- 新知识先作为短期记录保存，在设备空闲时（睡眠）固化进权重。已经实际复现了遗忘，并测量了睡眠的治疗效果。
- 教给设备 A 的知识可以由设备 B 回答，kill 掉 A 之后依然保留（CI `shared-mind-live`）[live]。
- 学了不同内容的两个大脑可以合并为一个（CI `one-mind-live`）。
- 重新教（把 sun→yellow 改成 sun→green）会替换旧答案而不混杂（CI `belief-revision-live`）[live]。
- 记忆满了的时候，最少被问到的知识会最先被遗忘。

局限：它只能学习词语对，不能组成句子。测量是在构造的任务上进行的，而非真实对话。详情：[living-mind.md](docs/architecture/30-module/living-mind.md)。

### 从白纸开始成长的大脑（婴儿）

词语关联的大脑只能学习固定的词汇。因此从 2026 年 6 月起，方针是不加载预训练模型，而是在设备上培养一个空白的小型语言模型。

- 它以适合设备性能的大小诞生，长成的权重在重启后依然保留。
- 从网页上和它说话，它会一个字一个字地回复。目前还说得磕磕绊绊。
- 老师是 SmolLM2-135M（公开模型），由不依赖任何外部库、用 C 编写的推理引擎运行。分发到群体中的只有学生，老师的权重不会分发。
- 用老师实际写出的句子训练后，对这些句子后续内容的预测变好了（损失 5.53→2.03；用固定教材训练同样步数的对照组为 6.61）。在单个进程内测量。
- 老师设备通过网络发送课程，老师被 kill 之后课程仍留在学生中 [live]（`samples/11_distributed/run_cradle_live.sh`，未纳入 CI）。不过，改善的大部分是记住了在训练侧也出现过的文本，而不是对未见过的文本的泛化。
- **量化**（2026-09）：`student quant <8|4|2> <row|g32|tensor>` 会把自身权重的副本舍入为 int8、int4 或 int2，并自行测量变差了多少。int8（按行）几乎没有变化（CI `st-quant`）。目前只做到测量，还没有以更小的形式保存自身。笔记：[brain-quantization.md](docs/architecture/30-module/research/brain-quantization.md)
- **合并的安全网**（2026-09）：简单平均两个大脑的权重，结果可能比较差的那一个还差。现在会尝试几种混合方式并选出最好的，绝不产生比较差的那个父代更差的结果（CI `st-merge`）。目前与其说是巧妙的合并，不如说是安全网。笔记：[brain-merge.md](docs/architecture/30-module/research/brain-merge.md)

### 安全机制（隔离与签名）

为将来自己改写代码的那一天，先把安全机制做好。

- 在 x86 上，大脑的计算运行在内核之外（ring 3）。即使它崩溃，内核也会存活并完成清理（CI `ring3-survival`）[live]。
- 设备为自己编译的代码，在权限受限的独立进程中运行。
- 要分发的代码用 Ed25519 签名。签名密钥属于设备，绝不与人的身份绑定。
- 借助兼容层和带签名的更新，不同版本的设备混在一起也不会让群体分裂。
- 设备改变自身状态的第一个操作（在自己的话题上发布）已经加入，并带有保护检查（2026-09）。

尚未完成：学习相关的代码仍在内核中运行，AArch64 上的同等隔离也尚未完成。

### 界面与应用

- **银河**：每台设备都有自己的页面（`http://127.0.0.1:7800`），把自己和同伴画成星星。星星的动态对应真实的睡眠和学习事件。
- **ark（Android 应用，0.9.x）**：安装后手机即成为一个节点。可以观看银河，也可以和成长中的大脑对话。只在充电时运行，加入前会征求对项目目的的同意。构建方法：[docs/android.md](docs/android.md)。
- 从不验证参与者的身份。实名、笔名和匿名一视同仁。

### 怀疑自身的机制

- **49 个 CI 任务**：五个目标的构建、中继测试，以及每次都会真正 kill 进程的测试。还会监视裸机内核的机器码是否在无意中发生变化（`crown-text-identity`）。
- 2026 年 6 月外部审计指出的 9 个问题（内存安全、签名检查缺失等）已全部修复。
- 反复 kill 和启动设备时偶尔会导致整个内核崩溃的 bug（KILL-CHURN），在排除了 7 个假设后找到了原因。其中一个假设，结果是由本意用来修复它的改动本身造成的——这是通过在同一天、用同样的步骤与未修复的内核对比才发现的。
- 尚未解决的问题统一放在 [gap-ledger](docs/architecture/gap-ledger.md)。目前有 3 个（2026-09-27）。

## 设计中 / 开发中

尚不声称能运行。

- **婴儿的成长**：更大的模型、更快的生成、日常地从老师的文本中学习。
- **联邦（federation）**：超越 64 台、迈向数千台，把群组进一步组织起来。目前只加入了第一部分（包含群组的 ID 格式），尚未用于通信。
- **p-fs 的后续**：与决定由哪台设备负责的机制整合，以及能够恢复丢失片段的存储方式。
- **GPU**：在设备 GPU 上运行大脑的计算。部件已经能运行，但接入大脑的工作暂缓。
- **隔离的剩余部分**：把学习相关代码移出内核，以及 AArch64 上的隔离。
- **密码学**：让 Ed25519 能够抵御计时攻击。

已设计但尚未验证的内容列表见 [V-MODEL.md](docs/architecture/V-MODEL.md)。

## 构想

是前进的方向，而非现在的样子。

- 宇宙飞船的一万块外部面板各自运行 p-kernel，只要还有一块存活，整体就不会停止。
- 整个网络成为一个大脑：群组是大脑的各个部位，快速反应与缓慢判断以不同速度运行，p-fs 是记忆。（睡眠和记忆共享已经能运行，但规模还称不上大脑。）
- 设备自己编写代码、签名、分发，整个网络一起成长。（隔离和签名的机制已经就位。决定该写什么的智能，还没有。）

整体的思路见 [survival-network.md](docs/architecture/00-concept/survival-network.md)。

## 试一试

**在一台机器上（Linux，约一分钟）**

```sh
sudo apt install -y build-essential
git clone https://github.com/monyuonyu/p-kernel.git
cd p-kernel/boot/linux                   # aarch64 机器
#  cd p-kernel/boot/linux_x86_64        # x86_64 机器
make && ./p-kernel
```

出现提示符后：

```
mind teach sky blue      ← 教
mind ask sky             ← 问（→ blue）
mind wait                ← 等待睡眠固化进权重
world                    ← 群体的视图
help                     ← 所有命令
```

- **看银河**：保持 `./p-kernel` 运行，在浏览器中打开 <http://127.0.0.1:7800>。也可以在那里和婴儿对话。
- **组成群体**：在另一个终端再启动一个 `./p-kernel`。在同一局域网内会自动连接。在一边教，在另一边问。
- **跨越 NAT 连接**：在 `relay/` 中 `make`（测试：`make test`）。在外部可访问的服务器上运行 `./relay`，各设备使用同一个密钥加入。
- **一台机器上的十台群体**：`samples/11_distributed/run_swarm_demo.sh`（x86_64 Linux，6 到 8 分钟）。一个节点学到的小型分类器（635 个参数，不是语言大脑）扩散到十个节点；逐个 kill 时其余节点继续回答，新加入的节点从最后的幸存者那里继承。这是一台机器上的十个进程，不是十台设备。
- **在手机上**：`android/` 中的 ark 应用（[docs/android.md](docs/android.md)）。
- **在裸机上**：在 `boot/x86` 或 `boot/aarch64` 中 `make`（附带用 QEMU 启动的脚本）。

## 目前的局限

1. **机制是真的，规模是玩具。** 学习、记忆、共享、纠正、遗忘都已分别测量。但大脑是约 21,568 个参数的词语关联模型，分类器只有 635 个参数。
2. **从未实际运行过 64 台。** 实际运行最多 32 台。数千台只存在于设计中。
3. **中继只认证，不加密。** 能防止冒充、篡改和重放，但不能防止窃听。
4. **Raspberry Pi 只到 QEMU 为止。** 还没有 SD 卡驱动。
5. **学习对算术的舍入方式很敏感。** 融合乘加的优化带来的舍入差异，曾经只在手机上破坏了学习。已经统一舍入方式使所有环境结果一致，但依赖于此仍是一个弱点。
6. **各目标的命令数量不一致。** 裸机 x86 有 59 个，裸机 AArch64 有 7 个，Linux x86_64 有 53 个，Linux aarch64 有 54 个（2026-09-27）。对照表见 [command-matrix.md](docs/architecture/command-matrix.md)，由源码自动生成并在 CI 中与实物核对。接下来会把它们拉齐。
7. **内核更换后的监视。** 迁移到 μT-Kernel 3.0 之后，仍用复现程序（`tcb_churn.c`）持续监视与 KILL-CHURN 同类的 bug。
8. **裸机 x86 上有一种尚未修复的卡死。** 如果某个任务一直运行而从不调用内核，内核就再也不会切换到其他任务（RNG0-BUSY-TASK-STALLS-DISPATCH）。原因已经清楚，修复方式正在决定中。CI 目前只做监视。
