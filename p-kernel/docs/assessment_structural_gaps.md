## 宣伝 vs 実態：決定的に抜けている穴

### 穴① 「自己進化／自己コンパイル」にコンパイラが入っていない 🔴 最大の欠落

README の目玉 *"The OS can compile and deploy new code to itself"* / `exec /tcc`。しかし：

- **リポジトリに TCC は 1 バイトも無い**（`git ls-files | grep -i tcc` → 空）。`arch/x86/shell.c` にも `tcc` 参照なし。
- `evolve` の実体は「状態収集 → **母艦の Python `claude_proxy.py` 経由で Claude API を叩く** → `[CODE]` を `/user/code_gen.c` に保存 → **"claude_proxy.py --compile で手動コンパイルしてね"**」（`arch/x86/shell.c:951`）。

つまり *自己* 進化ではなく **「ノート PC 上の Python に外注して、人間が手でコンパイルする」**。宣伝とのギャップが一番大きいのはここ。

**埋めるには:** libtcc をカーネル内（or ring-3）に実バンドル＋生成 ELF を実行中カーネルに戻して動的ロードする経路。ここが通って初めて「自己進化」を名乗れる。

---

### 穴② 「数千ノード／10,000 枚」が、実装は上限 8 ノード固定 🔴

README: *"thousands of nodes" / "unlimited nodes" / "10,000 spacecraft plates" / "more nodes = smarter"*。実態：

```c
// arch/common/include/drpc.h:35
#define DNODE_MAX 8   /* max nodes in cluster (node 0-7) */
```

`dnode_table[8]`、`[DNODE_MAX]` の固定長配列が全コードに散在。さらに複製は **3 秒ごとに全状態をブロードキャスト**（`arch/common/replica.c`）、トピックも O(N)。**設計自体が数千ノードに乗らない**（O(N²) トラフィック）。

**埋めるには:** 固定配列 → 動的管理、full-state broadcast → anti-entropy / 差分 gossip、ノード ID の動的割当。これは小修正でなく **スケーラビリティの作り直し**。

---

### 穴③ 「分散・非中央集権」を謳うのに relay が単一障害点(SPOF) 🔴

最新かつ最良の仕事である relay が、皮肉にも矛盾の核心：

```c
// relay/relay.c:10  "Single UDP socket, default port 7400."
```

**中央の 1 台の UDP フォワーダ**。コア思想は *"no single node can be trusted to stay alive" / "survives until the last node"* なのに、**relay が死んだら全通信が死ぬ**。relay の冗長化・発見・メッシュ化が無い。

**埋めるには:** relay の複数台化＋自動フェイルオーバ、もしくは P2P 直結＋relay は NAT 越え時のフォールバックに格下げ。

---

### 穴④ 「死なない OS」なのに、AI が ring-0 で落ちたらノードごと即死・復旧なし 🔴

`arch/common/heal.c` が救えるのは **ring-3 の ELF デーモンの再起動だけ**（DRPC 経由 / watchdog）。**カーネル障害ハンドラ（#GP / page fault からの復旧）が存在しない**。

看板機能の Transformer は ring-0（浮動小数点まみれ）で走るので、**1 個のバグ ＝ トリプルフォルト ＝ ノード全死、heal は無力**。README も SMEP/SMAP/canary を「TODO」と認めている。**一番死んではいけない場所に復旧機構が無い**。

**埋めるには:** AI 推論を独立 ring-3 タスクに隔離（カーネルから追い出す）か、カーネル例外 → 該当サブシステムだけ再初期化する復旧パス。

---

### 穴⑤ AI にモデルのライフサイクルが丸ごと無い（学習・保存・読込）🔴

- 重みは固定 seed `0xDEAD8888` の乱数（`arch/common/dtr.c:578`）。**同一アーキの全ノードは同じ"乱数"を共有** ＝「一貫した無意味」。
- しかも UMP は `normal`、ベアメタルは `CRITICAL` と **アーキ間で結果が違う**（実測）＝混在クラスタは **互いに矛盾した推論** をする。
- **学習済み重みをロードする経路もファイル形式も無い**。`arch/x86/persist.c` が保存するのは K-DDS トピックの `.dat` で、**重みは再起動で消える**（"survives" と矛盾）。
- `arch/common/fedlearn.c` の損失関数は `return (pred == label) ? 0.1f : 1.0f;` ＝ **偽の loss**。何も学習していない。

**埋めるには:** モデルファイル形式＋ロード経路、最低 1 個の **実学習済み重み**、再起動後リストア。

---

### 穴⑥ そして全ての宣伝が証明不能 — 測定機構がゼロ 🔴（構造的欠陥）

設計目標 *"more nodes = smarter / fewer nodes = more resilient"* を **誰も測れない**。精度メトリクスも、生存率ベンチも、ラベル付き評価セットも無い。**主張を反証も実証もできない** のが一番の問題。「凄い」を数字で語る土台が無い。

**埋めるには:** 小さくても評価データセット＋精度計測＋「N ノードで精度 X%／K 台落としても生存」を出す **ベンチハーネス**。これが宣伝を"事実"に変える唯一の道。

---

## 補足の穴（中）

- **NIC ドライバが RTL8139 の 1 個だけ。** 「Full TCP/IP」だが実機（RPi 等）では別ドライバ必須。移植性の主張が薄い。
- **分散推論は実質ローカル fallback。** relay 越しは timeout で脆く、3+ ノード FULL モードの安定動作デモが無い。

## 何が「ちゃんと動いている」か（公平のために）

穴ばかりではない。以下は実測で確認済み：

- ✅ x86 ベアメタルが QEMU で起動、**カーネル内 selftest 15/15 PASS**、シェル対話動作
- ✅ UMP(x86_64) がビルド・起動（README は "in progress" だが実際は動く＝過小評価）
- ✅ relay は HMAC-SHA256 / リプレイ防御 / nonce ウィンドウ / 鍵なし起動拒否、**テスト 6/6 green**（＝唯一、実務品質）
- ✅ Raft のリーダー選挙＋AppendEntries＋apply、SWIM、K-DDS、replica の CRDT 風 tombstone マージ

**骨格は本物**。だからこそ、上の 🔴 を埋めれば宣伝に近づける。

## 推奨ロードマップ（優先順）

1. **【誠実さ・即効】** README を実態準拠に（PR #3 参照）。誇張を外すだけで信頼性が激変。
2. **【穴⑥ → 土台】** 評価データセット＋精度/生存ベンチを 1 本。以後の主張が全部"測れる"ようになる。
3. **【穴⑤ → AI を本物に】** 学習済み重み 1 個をロード＆永続。`infer` が意味を持つ。
4. **【穴④ → 死なない を本物に】** AI を ring-3 に隔離、障害復旧パス。
5. **【穴③ → 非中央集権を本物に】** relay 冗長化 or P2P 化。
6. **【穴①②】** TCC 内蔵＋動的ロード、>8 ノードのスケール再設計（最も重い、最後）。
