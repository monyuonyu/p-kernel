## 1. 環化の検証 — 本物の閉ループか、自己申告か

第2版は「鎖であって環でない」と言い、A隊が環化を試みる。だが master を読むと、**環化に
必要な配線はすでに半分存在する**。問題は配線の有無ではなく、**閉じた先のループが何を制御
しているか**である。現存ループを実機の符号で追う。

### 1.1 現存する「負帰還ループ」の実体

```
推論 (dtr_log_push)
  └→ reflex_on_inference(threat_class)         dtr.c:281, dtr.c:1342
       └→ engage CONSERVE → conserve_until      reflex.c:148-149, 228
            └→ reflex_pressure_bias() = +40      reflex.h:67, reflex.c:272-277
                 └→ compute_pressure() に加算     world.c:144-148
                      └→ self-beacon + 自己観測    world.c:272, 300-307  (table[me] に載る)
                           └→ world_peer_pressure() world.c:229-233
                                └→ eff_pressure()   moe.c:168-174
                                     └→ expert_utility: u -= pressure  moe.c:159
                                          └→ select_expert が候補から外す moe.c:245-265
```

これは**位相的には閉じた負帰還ループ**である(reflex の出力が次の推論の経路選択に戻る)。
A隊が G17 で `moe_infer`→`reflex` を繋げば(`moe.c:340-377` に現在 reflex 呼びなし)、
両推論経路がこのループへ入る。**環は閉じる。** だが——

### 1.2 閉じた環が制御しているのは「脅威」ではなく「負荷」である(符号の倒錯)

`expert_utility` は pressure を**ペナルティ**として引く (`moe.c:159`)。つまり pressure が
高いノードは「混んでいる＝委譲先として不適」と解釈される。CONSERVE はこの pressure を
+40 する (`reflex.h:67`)。さらに `world_observe(&self)` で**自ノードも自分の pressure を
table[me] に載せる** (`world.c:294-307`)。結果、CONSERVE 中のノードは:

1. **自分自身の self-utility が下がり**、自分の緊急推論を**他ノードへ送り出す** (`moe.c:245-247`,
   self も一候補)。= §8 が「反射は近傍で即応・大域遅延に乗せるな」と言う、まさにその逆 —
   threatened node が自分の判断を遠方へ投げ、光速遅延を足す。
2. **隣も避ける** — BEACON で alarm を撒き (`reflex.c:128`)、受信側は減衰 CONSERVE を engage
   して**自分の pressure も上げる** (`reflex.c:221-228`)。近傍一帯の pressure が上がる。

survival §2 の核は「**守る対象＝目の前の一点に、全網の総合力を注ぎ込む**」。だが実装の
reflex/CONSERVE は **threatened node から群れの計算を遠ざける符号**を持つ。単一スカラ
`pressure` が「混んでいる(仕事を送るな)」と「危ない」の**両方**を意味し、両者が要求する
ルーティング応答は**正反対**なのに、コードは両方を「このノードを避ける」へ畳んでいる。
「忙しい」には正しいが、「危ない・群れの力が要る」には**真逆**。→ **G20 (🔴)**。

(注: §2「一点へ注ぐ」は *requester 軸*=DKVA fan-out では実装されている —
threatened node が DKVA query を出せば他ノードが partial を寄せる。しかし *expert 可用性軸*
=reflex/CONSERVE はそれと**逆向き**に働き、近傍を CONSERVE に落として DKVA fan-out の
helper 在庫を減らす。思想の二つの半身が干渉する。)

### 1.3 解除はタイマであって誤差ゼロではない(自己申告の閉ループ)

`check_release()` は `now >= shield_until / conserve_until` で**のみ**解除する
(`reflex.c:243-257`)。until は `now + REFLEX_HOLD_MS`(5000ms 固定, `reflex.h:55`)。
危険を**縮める actuator は存在しない** — SHIELD はコード取り込み拒否、CONSERVE は負荷
偏向、BEACON は警報。どれもセンサ値(threat_class の源)も環境も変えない。よって:

> 「危険がスパイク→やがて沈静化」という観測は、**5s タイマの満了**(または class=0 の
> 新推論到着、`reflex.c:170`)であって、ループが脅威を是正した結果**ではない**。

これは task §1「指標が改善したように見えるが実は**外乱の自然減衰**」そのもの。C隊の複合
テストが「pressure が上がって下がった」を緑にしても、それは**ヒステリシス・タイマが
動いた証拠**であって**環が閉じて収束した証拠ではない**。制御量(脅威)に actuator が無い限り、
このループは「自己申告の閉ループ」である。→ **G21 (🔴)**。

### 1.4 熟慮→学習は「学習」でなく「事前に決めた適応則の実行」

A隊の G18 方向(熟慮を学習へ)は閉じない。理由:

- 熟慮 tick は **score gossip + accuracy 再計算**のみ (`moe.c:449-468`) = 選択のローパス。
  重みは一切動かない。
- 分散 FedAvg は正直に `E_NOSPT` (`fedlearn.c:165-183`)。
- 局所学習 `fl_local_train` ですら **635 パラメータ中 b3 バイアス 6 個**の有限差分のみ
  (`fedlearn.c:98-119`, `for j<MLP_OUT`)。
- 動いている適応(`recent_pick` 減衰 `moe.c:217`、EWMA `moe.c:179-184`、deadband
  `moe.c:191-202`)は**すべて事前に固定した適応則の実行**であって、経験からパラメータを
  書き換える学習ではない。

「経験から自分を書き換える」(§9 考える器官)は、master では**一台の中でも 6 パラメータ**しか
書き換えられない。A隊が fedlearn を配線しても、閉じるのは「6 バイアスの有限差分を平均する
環」であって、思想が言う学習の環ではない。→ **G22 (🟡)**。

### 1.5 §8 二層が環化で生む新たな発振リスク

G17 で moe_infer を reflex に繋ぐと、**同じ pressure スカラに二つの速い信号が乗る**:
reflex CONSERVE(`+40`, 5s 保持)と recent_pick 自己仮想負荷(`+25`/pick, 2/3 減衰,
`moe.h:96-98`)。空間相関した脅威(デブリ帯・放射線が装甲板クラスタを同時に叩く=実ユース
ケース §3)では:

- 近傍が**一斉に** CONSERVE(`reflex.c:221-228` の alarm 連鎖, hop=1)→ 近傍全員の pressure 上昇
- → `select_expert` の全候補 pressure が底上げ → utility 差が潰れ、RTT/accuracy ノイズが
  支配 → incumbent thrash(deadband `MOE_SWITCH_MARGIN=12`, `moe.h:117` を超えやすくなる)
- → 「応援・受援」勾配が**ゼロに平坦化**。脅威が最も深刻なときに**助けが流れない**(§6 の前提
  「脅威と余力は無相関」を reflex が壊す)

`[moe-osc]` 性質テスト(`moe.c:516-532`)は**この相関入力を注入しない**(純ローカル 3 ノード,
無相関)ので、緑のまま発振を見逃す。→ **G20/G21 の系として記録**(発振は符号倒錯の帰結)。

## 4. 思想の未踏の核 — §2「守る対象」と最上位目的との距離

第2版 I18 が「守る対象がコードに無い」と指摘した。第3版はそれを**核心の符号問題**へ昇格する。

### 4.1 「守る力」は揃いつつあるが、「守る対象」は実体として無く、しかも符号が逆

- **守る力(計算/行動)**: DKVA 分散 attention、moe ルーティング、reflex 三行動 — 実体あり。
- **守る対象(守るべき一点 = protected unit)**: コードに**オブジェクトとして存在しない**
  (grep: `protect`/守る対象 は memory-protect 等の別概念のみ)。reflex の act_table
  (`reflex.c:51-55`)は class→action の翻訳であって「何を守るか」を持たない。
- **しかも符号が逆(G20)**: §2 は「守るべき一点へ全網の力を**注ぐ**」。だが threatened
  node は CONSERVE で pressure を上げ、群れに**避けられる**。「守る対象」が概念として無い
  だけでなく、**実装の力学は守る対象を群れから切り離す方向に働いている**。

これが「絵に描いた餅」の最たる章: §2 は思想の最独自点(付記が「設計判断のたびに立ち返れ」と
名指す核)なのに、コードでは(a) 対象オブジェクト不在、(b) 力学が逆符号。survival §5/§7/§9 は
性質テストや DKVA で部分的に接地したが、**§2 だけが接地しておらず、しかも逆を向いている**。

### 4.2 最上位目的「人類が滅んでも生き残り、人類を再起動する」に決定的に欠けているもの

優先順に **3 つ**(G24):

1. **耐久永続の物理的担保(最も決定的)**: p-fs durable backend は TODO、P0 は in-memory
   (`pfs_block.c:13-24`)。生存は RAM + peer 複製(生存者前提, `replica.h:7`)。全ノード同時
   電源喪失=全損 — それは「人類が滅ぶ」級の災害そのもの。**生きた群れから独立した冷温
   保存**が無ければ、保存の図書館(§9 の前提条件)が満たされない。
2. **ペイロード=人類の知の不在**: 配られるのは群れ自身の玩具ゲノム(635 param + 32 engram)
   であって人類の知ではない(`retrieval.c:14`, `genome.c:280-296`)。「再起動する人類」の
   中身が無い。
3. **再起動シーケンスの自己記述の不在**: 「どう人類を再起動するか」の手順オブジェクトが
   コードに無い(grep ゼロ)。

> つまり現在の p-kernel は「**自分自身を生かし続けるネットワーク**」としては環化しつつ
> あるが、「**人類を保存し再起動する器官**」としては、保存(耐久)・中身(人類知)・手順
> (再起動)の三点すべてが未着地。最上位目的に対しては、思考の器官以前に**図書館がまだ
> 揮発メモリ**である。
